## 数値と共通の発動規則

1秒は既存の60,000時刻単位、表示コスト1は内部整数4である。以下を少数の効果別SimConfig項目として追加し、sessionのconfig合意へ含める。攻撃・防御・敏捷、危険倍率、ラリー、オーバーチャージでスキルの速度・幅・時間を変えない。

| 項目 | 初期案 |
|---|---|
| 3スキルのコスト／枠CT | 各2（内部8）／10秒（600,000） |
| トラップ | 半径0.75m、水平設置距離32m以内、予兆0.5秒（30,000）、起動後8秒（480,000）、スタン0.3秒（18,000） |
| チェーン | 予備動作0.3秒（18,000）、速度18m/s、飛翔体半径0.18m、射出後寿命2秒（120,000）、引き寄せ0.25秒（15,000） |
| エナジーボルト | 予備動作0.3秒（18,000）、速度18m/s、飛翔体半径0.18m、射出後寿命2秒（120,000）、非保持者のスタン0.35秒（21,000） |
| 転送 | 0.35秒（21,000）。移動距離によらず一定時間 |

発動にはplay・dangerあり・本人が生存し、0014の通常のスキルゲートを満たすことが必要である。3種はcatch-whiffを解除できない。開始時刻より後のfeintだけは、全検査に成功してから解除する。windup・recovery・防御・空振り・step・hitstun、後述の拘束・スキル予備動作中は発動不可である。保持／非保持は問わない。

判定順は既存の未実装・phase・ko・busy・cooldownを維持し、その後に共有待機、既存設置物／同種飛翔体の存続、cost、設置地点を検査する。存続はbusy、共有待機には新しい`shared-wait`を使う。CT・支払いの失敗は状態を変えない。新しいコスト予約・返金処理は作らない。CT・耐性・共有待機は論理絶対時刻の比較とし、期限ちょうどから解除される。

## 入力、発動時の照準、予備動作

### Command

既存の押下Commandを維持し、設置の確定と意図的な取消だけを追加する。

```ts
// いずれも既存の at / seq / player を持つ。
{ kind: 'skill'; slot: 1 | 2 }          // 押下。即時型の開始、設置型のプレビュー開始
{ kind: 'skill-release'; slot: 1 | 2 }  // 通常のキー解放。プレビューがあれば確定を試す
{ kind: 'skill-cancel' }               // 入力抑止などによる本人のプレビュー取消
```

主副キーをORした行動のfalse→trueで押下を1回、true→falseで解放を1回送る。一方を離しても他方を保持していれば解放しない。repeatを除外する。即時型・パッシブの解放と、プレビューなし／別枠の解放は無処理で、拒否通知も出さない。受理しなかった押下を解放時に改めて発動しない。

プレビュー中もmove・keys・yaw・pitch・Qを通常どおり更新する。地点は各時刻の姿勢から計算し、Commandへ座標・対象ID・カメラ姿勢を載せない。プレビュー開始は同時刻の1行動を使うが、保持し続けることはactionを占有しない。

同時刻は状態入力（move・keys・yaw・pitch）とQを先に反映し、0014の「ステップ ＞ キャッチ ＞ 跳ね返し・投擲 ＞ 枠1 ＞ 枠2 ＞ フリ ＞ 召喚」を維持する。skill-releaseの設置確定も該当枠の順位へ置く。枠ごとの同時重複は同種で最小seqの1件だけを使う。同じ枠の押下と解放が同時刻なら、プレビューがあれば解放だけ、なければ押下だけを評価して直後に無消費取消し、ゼロ時間の設置を成立させない。到着順や配列順で結果を変えない。

左クリックに相当するprimaryは、成立の可否にかかわらず、行動評価より先にプレビューを取り消す。その時刻の押下による再プレビューと解放確定も抑止する。その後、通常の投球／跳ね返しを元のゲートで試す。ステップ・キャッチ・フリ・召喚・他スキルは、成立した場合だけプレビューを取り消す。上位行動が成立した解放は捨ててプレビューも消し、後刻の自動設置にしない。プレビュー中の同じ枠の再押下は無処理、別枠の新しいプレビューへの切替はbusyとする。取消自体は行動枠・資源を使わない。

blur・ポインタ捕捉解除・Esc・設定適用・入力抑止は通常解放と区別し、送信可能ならskill-cancelを送る。releaseAllを設置確定に変換してはならない。同時刻のcancelは確定・開始より優先し、通常行動は妨げない。通信中断時は送信しない。再開時に確定stateへ戻ったプレビューが残る場合、再開最初の入力時刻に各クライアントが本人のcancelを送ってから新しい操作を許可する。ホスト本人にも適用する。キャンセル再送は無害で、HeldInputへスキル保持を追加しない。保存リプレイ自体はプレビューをそのまま復元し、接続復帰の入力リセットと区別する。

### 即時型の射線

本書の「発動時刻」は**押下が受理され、予備動作を開始する時刻**である。即時型とは解放による確定が不要という意味で、弾が待ち時間なしに出る意味ではない。その時刻の最新のyaw／pitch・位置・生存敵を`aimLine`へ渡し、返されたoriginとdirectionを予備動作へ保存する。Q、ADSの有無、FPS/TPS、表示カメラは使わない。

予備動作0.3秒は足を止め、射出は保存したorigin／directionから行う。yaw／pitch・Q・移動キーの意図は更新できるが、照準し直し・歩行・ステップ・他の行動はできない。足を止めるのは発動時の射線を守り、移動後に元の手の位置から弾が出る不整合を避けるためである。予兆の腕の向きも保存した方向を使い、視点を強制回転しない。

これは0015末尾の「後続スキルも射出時の最新角度を使う」という暫定引継ぎを、本依頼の発動時照準へ具体化して置き換える決定である。0015の通常の狙い投げは従来どおりリリース時に照準を確定する。共有するのは`aimLine`の幾何であり、通常球の投球中再照準まで同一にしない。

開始時にコスト8を支払い、使用枠のCTを10秒開始する。予備動作中に通常球の直撃・スタン・引き寄せ・KO・爆発・ラウンド終了が起きれば中断し、弾は出ず、支払いとCTを戻さない。手動取消と防御による中断操作は追加しない。開始後のキー解放は何もしない。0.3秒の終了時刻は既存windupと同様に射出を先送りして同時刻入力を待ち、その時刻の新しい行動はbusy、射出後にactionをnullへ戻す。追加の射出後硬直はない。後述の同時刻順位では射出が接触より先なので、射出ちょうどの被弾は既に出た弾を取り消さない。

## 最小の状態

以下は型の設計案であり、コードの追加済みを表すものではない。名称はこの契約へ統一し、互換フィールドを作らない。

```ts
// PlayerStateへ必須追加。初期値はnull、null、0。
trapPreview: { slot: SkillSlot } | null;
control: { kind: 'stun'; endsAt: number }
  | { kind: 'pull'; startedAt: number; endsAt: number; origin: Vec3; destination: Vec3 }
  | null;
controlImmuneUntil: number;

// 既存actionのunionへ追加。
{ kind: 'skill-windup'; skill: 'chain' | 'energy-bolt'; slot: SkillSlot;
  startedAt: number; endsAt: number; origin: Vec3; direction: Vec3 }

// SimStateへ必須追加。初期値は各[]と{ a: 0, b: 0 }。
traps: { owner: PlayerId; slot: SkillSlot; placedAt: number; position: Vec3;
  activatesAt: number; expiresAt: number;
  pendingContacts?: { at: number; players: PlayerId[] } }[];
chains: { owner: PlayerId; slot: SkillSlot; releasedAt: number; origin: Vec3;
  direction: Vec3; expiresAt: number;
  pendingContacts?: { at: number; players: PlayerId[] } }[];
bolts: { owner: PlayerId; slot: SkillSlot; releasedAt: number; origin: Vec3;
  direction: Vec3; expiresAt: number;
  pendingContacts?: { at: number; players: PlayerId[] } }[];
teamControlReadyAt: Record<Side, number>;

// BallStateのunionへ追加。唯一のballそのものを置き換える。
{ mode: 'transfer'; side: Side; toSide: Side; startedAt: number; endsAt: number;
  origin: Vec3; destination: Vec3; position: Vec3 }
```

トラップはownerあたり1個、chain／boltもそれぞれownerあたり1個を上限とする。同じ効果の重複枠でも増やさない。自分の同種弾が残っている間は次の予備動作を開始できない。効果の一意な識別は種類・owner・slot・placedAtまたはreleasedAtで足り、IDカウンタを作らない。配列はowner、slot順で保存する。

chainとboltは種類ごとの小さい状態・処理を持つ。speed・radiusはconfig、sideはownerの固定所属から導く。現在位置はoriginと経過時刻から算出し、表示とsimで積分しない。controlのpull位置も始終点の絶対時刻補間で求め、PlayerState.positionへ反映する。防御actionとcontrolが併存できるため、actionを単一の巨大な拘束状態へ置換しない。

設置プレビューの地点・有効性は純粋な地点計算から導き、状態には重複保存しない。耐性終了・共有待機終了は時刻比較だけで、0へ戻すイベントは不要である。開始時の参加人数はplayersの固定所属から導き、現在の生存人数で1v2を判定しない。2v2で一人KOしても共有待機の対象にはならず、1v2の二人側が一人KOしても規則を解除しない。

## 02 スクラップ・トラップ

### 地点と確定

本人の論理的な目Eとyaw／pitchの視線D（0015）を地面y=0へ伸ばし、正の交差距離から地点Pを求める。`aimLine`の敵カプセルや白線垂直面で止まるTを地面へ投影してはならない。下を向かない場合は地面候補なしである。地面用の短い純粋関数を表示とsimで共有し、Raycasterや汎用ターゲット選択は作らない。

Pは相手陣、本人の足元から水平32m以内、かつ半径0.75mの円全体が白線矩形の相手側半面に入る必要がある。白線の物理位置は`W = ballHalfWidth + ballDiameter/2`、`D = ballHalfDepth + ballDiameter/2`で求める。`abs(P.x) <= W - 0.75`、相手側の深さ`0.75 <= depth(P) <= D - 0.75`とする。境界を含む。

相手陣の供給位置からの水平距離は、トラップ半径＋capsuleRadius＋pickupRadiusより**大きい**必要がある（既定値2.25m）。これにより供給位置とその通常回収域を踏み範囲で封鎖しない。敵の現在位置との重なりは許容するが、必ず0.5秒の警告後に起動する。両チームのトラップ同士は干渉しない。壁・中央・範囲端へ自動クランプしない。

押下では共通ゲート・残高・CT・共有待機・自分の既存トラップを検査し、地点がなくてもプレビューを開始できる。資源は取り置きしない。解放時は最新姿勢の地点と全条件を再検査する。成立した時だけコスト8・CT10秒を確定し、`placedAt=now`、`activatesAt=now+0.5秒`、`expiresAt=activatesAt+8秒`の1個を置く。成否によらずそのプレビューを消す。不成立はskill-rejectedを1件通知し、資源・CTを変えない。既存物の交換や回収操作はない。

### 踏み判定

有効区間は`[activatesAt, expiresAt)`である。警告中は敵が重なっても何も起きず、起動ちょうどに中にいれば踏む。円とキャラ足元の水平カプセル投影が触れた最初の時刻、すなわち中心間距離が`0.75 + capsuleRadius`以下となる連続接触を使う。通常歩行・ステップ・引き寄せ・ノックバックの区間速度で掃引し、60Hzの位置だけを点検して通り抜けさせない。ブリンクは経路を踏まず、到着点だけを検査する。

生存する敵に最初に触れた時に1個を消費する。味方・KOは踏まない。同時候補はトラップ中心への水平距離、PlayerIdの順で一人を選ぶ。耐性・既存拘束・hitstun・共有待機によりスタンを付けられなくても消費し、無効対象を飛ばして別の人へ当てない。起動時の重なりも同じである。成功時は0.3秒スタン、HPダメージ0である。

## 06 チェーンハンドと07エナジーボルトの飛行

### 共通の幾何だけを再利用する

保存したoriginからdirectionに沿って等速直進する。重力・追尾・Q対象・返球・貫通はない。生存敵全員の既存カプセルに、飛翔体半径0.18mを加えた合成半径0.48mで`sweptCapsuleContact`を使う。既存のcapsuleBottom=0.30m、capsuleTop=1.50mを使い、見た目の鎖の長さやモデルの骨で判定しない。頭上・足元も3次元で判定する。

最初の人物接触で弾を消す。複数人の同時候補は弾中心からカプセル軸線分への3次元最短距離、PlayerIdの順とする。味方・KO・通常球・別のスキル弾・設置物には接触しない。キャッチ・跳ね返しで弾を防ぐことはできず、防御報酬・ラリー・hitイベントは発生しない。ステップとブリンクにスキル無敵を追加しない。

飛翔体の床・外周は0015と同じ白線の物理平面を使い、**スキル自身の半径**で内側へ縮める。`y <= 0.18`、`abs(x) >= W-0.18`、`abs(z) >= D-0.18`で消す。初期位置が外または境界上なら、内向きでも射出時に消す。開始済みの支払い・CTは戻さない。人物接触と消失が同じ丸め時刻なら、内側から飛行してきた弾は人物接触を先にする。初期位置不正は人物判定前に消す。

中央フェンスは通過し、スキルが中央を横切っても危険時計を変えない。白線外の金網へ到達する前に消える。天井・任意メッシュとの衝突は追加せず、上向きの弾も射出から2秒で消える。寿命区間は`[releasedAt, expiresAt)`で、期限ちょうどの接触は無効である。消えたスキル弾をlooseの通常球に変換しない。

### チェーンの命中

命中者の陣の前面、`x=命中時の本人x、y=足元y、z=本人陣の符号×playerMinDepth`へ0.25秒で線形移動する。相手陣とは発動者から見た敵陣であり、自分側へ連れ込まない。xを攻撃者へ寄せず、攻撃者の移動も追わない。キャラ中心の合法長方形は凸なので、この区間は壁・中央を越えない。白線はキャラの移動境界ではなく、白線の外にある合法xも維持する。

既に前面にいて始終点が同じ場合は弾を消すだけで、拘束成功・耐性・共有待機を発生させない。移動する場合だけpullを開始する。保持球はheldの同じownerについて動き、時計・ラリーは変えない。追尾球への解除効果はなく、通常球は移動中のカプセルへ通常どおり接触する。

### ボルトの命中

命中を処理する瞬間の`ball.mode === 'held' && owner === 命中者`で分岐する。発射時点の所持や、同時刻入力前の所持を記憶してはならない。

- 保持者なら強制落球して直ちにtransferへ遷移する。中間のlooseを物理・召喚・回収へ公開しない。スタンは付けず、既存の通常投球windupが残っていれば消す。その他の防御後硬直等は維持する。
- 非保持者なら0.35秒スタンを試す。すでに球がflight・loose・transferである場合はその球へ一切干渉しない。

拘束耐性と既存拘束はスタン・引き寄せに対する規則であり、保持者の落球・転送は防がない。転送だけでは耐性も共有待機も付けない。飛翔中に共有待機が始まっても保持者への転送は成立するが、新しいボルト発動は共通ゲートで止める。この区別は「拘束」を所有権変更全体へ広げないためである。

## 拘束、行動、耐性、共有待機

| 状態 | 移動・入力・通常球の扱い |
|---|---|
| stun | 歩行・ステップ・投球・防御・フリ・召喚・全アクティブ開始を不可とする。開始時にactionとプレビューを消す。保持球を落とさず、looseの自動回収は不可 |
| pull | 通常移動を始終点補間で置き換える。非保持者のキャッチ・跳ね返しを通常の発生・受付・正面条件で許可する。既存catch/parryとその回復・空振りは維持し、他のactionとプレビューは消す。投球・ステップ・フリ・召喚・全アクティブ開始は不可。通常の物理境界でlooseを回収できる |
| いずれも | yaw・pitch・Q・move・keysの状態入力は受け付ける。将来の行動予約はしない。終了時は最新の移動意図で再開し、押し損ねた投球や防御を自動実行しない |

引き寄せ中にキャッチした球は同じownerのheldとなり、以後の投球はpull終了を待つ。跳ね返しはkeys／Qと現在位置で既存どおり成立する。防御後硬直はpullと独立に期限まで続く。引き寄せが終わることを理由に防御actionを消さない。カメラのyaw／pitchを操作せず、位置だけsimへ追従する。

拘束命中時に、対象がcontrol中、`now < controlImmuneUntil`、通常球のhitstun中、または攻撃側の共有待機中なら、新しい拘束を付けない。既存拘束の延長・上書き・二重化はしない。無効な命中でも弾／トラップは消え、支払い・CTは戻らない。拘束耐性中でも通常球の直撃・爆発・防御は通常どおりである。オーバーチャージ予約は生存中のスキル拘束では消さない。

拘束が自然終了した時刻tにcontrolを消し、`controlImmuneUntil=t+1.5秒`とする。通常球の直撃が拘束中に発生したら、その時刻で拘束を終了して耐性を付け、通常のhitstunとノックバックへ置き換える。短いスタンが通常球のhitstunを消すことも、引き寄せがノックバックを打ち消すこともない。KOではcontrol・preview・actionを消し、再拘束は生存条件で止める。

開始時1v2の二人側だけは、スタンまたは実移動するpullを付けた時刻tに`teamControlReadyAt[攻撃側]=t+3秒`とする。付与した人のCTとは独立で、味方全員の3種の新規開始／設置確定を止める。既にある設置物・弾にも命中時の共有待機を適用する。待機中に踏まれた物／命中した弾は消費され、その時刻を基準に待機を延長しない。同時成功候補も最初の1件だけを成功とする。単独側、1v1、2v2はこの値を0のまま維持する。

爆発では、全員のプレビュー・スキル予備動作、全設置物・スキル弾・拘束を消す。生存者の中断した拘束には爆発時刻から耐性を付け、既にある耐性・CT・共有待機は実時間ではなくsim時刻で進める。dangerなしの間に残留スキルが新たに命中する状態は作らない。本人KOでは本人の未射出予備動作を消すが、配置・射出済みの効果と進行中の転送は他人のKOまで巻き戻さず存続する。ラウンド終了では全効果と転送を消し、ballを既存の結果待機用absentへ統一する。次ラウンドでCT・耐性・共有待機を0、追加の可変状態をnull／空配列へ戻す。

## エナジーボルトの球転送

保持球の論理位置、すなわち命中者の足元＋defenseHeightをoriginとし、攻撃者の陣の`config.supply[side]`をdestinationとして固定する。攻撃者の手元や現在位置へ追従しない。射出済み攻撃者がKOしても固定所属は変わらない。

`ball = transfer`へ一度で置換し、開始時にrallyを0へ戻す。attack・owner・homing・pendingContactsは転送modeへ持ち込まない。表示上は手から離れる一つの球である。`position = origin + (destination-origin) × (now-startedAt)/(endsAt-startedAt)`、`endsAt=startedAt+21,000`とし、直線の見える軌道で中央を横切る。転送はダメージ・キャッチ・跳ね返し・拾得・召喚・別ボルトによる奪取の対象にならない。スキル弾の白線消失とlooseの中央反射は適用しない。転送始点が白線外でも、合法な保持位置から供給位置への区間はケージ内にある。

転送開始で危険時計を止めたりリセットしたりしない。現在のsideは最初は命中者の陣で、dangerもその期限を維持する。中央時刻は`startedAt + ceil(21,000 × (-origin.z)/(destination.z-origin.z))`で一度求める。そこへ到達した時だけsideをtoSideへ変え、既存のcrossingを1件出し、`danger={side:toSide, expiresAt:crossingAt+8秒}`とする。二度目の通過処理は`side===toSide`により除外する。位置の丸め後にzが反対側へ微小に進んでいても、通過前の爆発責任は保存したsideを使う。

転送前・転送中を問わず、旧時計が中央通過より先、または同じ整数時刻に8秒へ達したら爆発が先である。転送球を消し、通常の爆発ダメージ・反対陣への新球待機に進み、転送完了もcrossingも発生させない。たとえば転送開始から通過まで0.175秒、残り時計0.100秒なら元陣で失敗する。残り0.175秒ちょうども同じである。通過済みなら以後は攻撃者側の新時計である。

0.35秒後はdestinationのlooseへ置換する。初速0、`startsAt=完了時刻`、`motionAt=完了時刻`、`nextPhysicsAt`は厳密に次の絶対60Hz境界とする。完了時の手元回収・即拾得はない。供給位置で待つ人も次の通常物理境界で回収する。召喚は転送完了後の新しい入力から既存条件とコストで使える。完了でspawn／clock-startを出さず、中央で始まった時計を再リセットしない。球数は常にballという1状態であり、absentの通常新球待機以外で0個や2個にしない。

## 次事象と同時刻の処理順

既存の整数時刻・60Hz・入力区間`[tick開始, tick終了)`を維持する。次事象へ予備動作終了、トラップ起動／期限／踏み、スキル弾の人物／床外周／寿命、拘束終了、転送中央／完了を足す。幾何計算は実数で最初の交差を求めて絶対時刻へ一度だけceilし、移動速度や位置が変わる入力・壁到達・拘束境界で再探索する。入力のない区間でも全期限を進める。

| 順 | 同じ整数時刻tで処理すること |
|---|---|
| 1 | tまで位置を進め、爆発を最優先する。転送中は保存sideで責任を決める。爆発で消えた球・効果の古い候補を捨てる |
| 2 | 予約・物／弾の寿命・拘束の終了、供給と時計開始、既存action終了。期限ちょうどの物は命中しない。拘束終了では耐性を付ける |
| 3 | 状態入力・Q、取消、個人の優先順の行動。続いて通常球リリースとスキル射出。通常投球windup／skill-windupの終了ちょうどの新行動は不可 |
| 4 | 既存flightまたはtransferの中央通過。トラップとスキル弾の中央通過はここへ追加しない |
| 5 | 通常球の有効防御 → 直撃 → 攻撃消失・既存誘導更新 |
| 6 | トラップ起動と踏み、チェーン／ボルトの命中を共通の確定順で解決し、床外周消失を処理する。HPが0になった対象はここで除外する |
| 7 | 転送完了 → looseの既存物理・回収。新しく作ったlooseは次の物理境界まで回収しない |
| 8 | 勝敗を一度決定する |

通常球を先にするので、同時のキャッチ成功者へボルトが当たれば保持者として転送する。同時の手投げリリース／跳ね返し後なら非保持者としてスタンを試し、飛んだ球を奪わない。通常球直撃でhitstunへ入った人物にはその時刻の新拘束を付けない。直撃によるHP低下をスキルの直接ダメージとして数えない。

同時刻の複数スキル接触は、**ownerのPlayerId → slot → 種類（trap、chain、energy-bolt）→ 生成時刻**で解決する。配列順・seq・到着順で変えない。同じ整数時刻に丸めた候補に小数の隠れた先着順を持たせない。各物の対象は前述の距離→対象ID順で一人とし、先の結果で所持・生存・拘束・共有待機が変われば、後の効果は変更後の状態を検査する。2本のボルトでも球は1回だけtransferへ入り、後のボルトは非保持者へのスタン分岐となる。

ブリンクした当人の移動前の接触候補だけを破棄し、到着点を再検査する。移動経路を踏ませず、他人の接線候補は残す。スキル予備動作中はブリンク不可だが、飛翔中の弾をブリンクで避ける場面には適用する。

tick終了ちょうどでは爆発・期限・中央通過を先に確定する既存規則を維持し、入力を必要とする射出・人物接触・トラップ起動接触・転送完了・物理・勝敗は次tickの同時刻入力後に解決する。切り上げ前の接線接触を失わないよう各物のpendingContactsに候補を保存する。射出はaction、完了はtransferのendsAt、起動はactivatesAtが境界を保存する。床外周消失も同時刻に人物候補があれば次tickまで待つ。候補の消費、物の削除、mode変更、次事象更新のいずれかを必ず行い、同時刻を無限反復しない。

## 保存復元・受信検査・PROTOCOL

追加フィールドを初期化、structuredClone／JSON保存、予測と確定state、ホスト再実行、sync／resume／completeへすべて含める。プレビュー、予備動作、接線境界、拘束中、耐性／共有待機、中央前後の転送を復元して同じ入力の続きから同じstateとeventsへ到達することが条件である。描画時刻・ローカルの押下フラグをsim再実行に必要な状態にしない。

PROTOCOLを**4から5**へ上げ、room・session・Worker・クライアント・fixtureを同じ形式へ揃える。別の形式変更が先行した場合はその時点の次版へ統合する。旧Commandのskill押下は現行の操作として残すが、新しい必須stateの欠損を補う互換経路は作らない。設定保存の形式とversionは変えない。データ移行や既存データ削除はしない。

受信検査は新しいCommand・event・stateの各分岐について必須項目と許可キーを列挙する。概略mode検査だけでtransferを通さない。

- slotは1／2、IDは参加者、時刻は非負の安全な整数、Vec3は各成分が有限である。directionはノルム1（許容誤差1e-9）の有限ベクトルとし、非有限値・欠損・疎配列・余分な座標引数・未知のkind／reasonを拒否する。
- previewはtrap枠を指す。windupは該当chain／energy-bolt枠と整合し、開始≦now≦終了、期間0.3秒、保存originは本人の停止位置＋defenseHeightと整合する。中断後にwindupだけ残る状態は拒否する。
- controlはstun／pullの排他的unionで、生存者のみ、終了≧nowとする。pullは期間0.25秒、始終点が本人陣の合法範囲、到着zが前面、nowの補間位置が本人positionと一致する。active controlと将来のcontrolImmuneUntilは併存しない。hitstunまたはskill-windupとcontrolの併存も拒否する。耐性の過去の期限自体は合法である。
- traps／chains／boltsは参加者数以内かつownerの同種重複なし、枠の効果と整合する。期限の差、配置の固定領域と供給除外、弾の寿命・単位方向を検査する。配置距離は設置後に本人が動くため現在位置から再検査しない。KOしたownerの射出済み効果は合法である。
- pendingContactsはnowの終了境界だけ、実在する敵IDを重複なしで持つ。味方・未知ID・過去や未来の境界を拒否する。丸め済みの幾何再判定だけで正しい接線候補を拒否しない。
- transferは正確に0.35秒、開始≦now≦終了、originが送り出し側の合法保持位置、destinationがtoSideの供給位置、両端zの符号が逆、positionが時刻補間と一致する。sideは中央処理済みかどうかと整合し、danger.sideとも一致する。owner／attack／velocity等の別modeの項目を許可しない。中央前は元陣、中央ちょうど以後の保存stateはtoSideとする。
- 座標の算術一致は絶対誤差1e-8m以内で比較し、受信値を補正しない。生成時刻が必要な新効果は未来を許可せず、境界で未処理の終了時刻＝nowを許可する。完全に処理済みの期限切れ効果を受信で正規化しない。
- 共有待機は固定構成が1v2の二人側だけ非0を許す。非playの新効果は空、拘束・previewはnullとする。開始ロスターのID・side・stats・maxHp・skillsの照合は既存どおり全snapshotで行う。入れ子のstate.inputs、events、sync、resume、completeにも同じ検査を適用する。

通信は既存の本人認証・seq重複排除・100msの再実行範囲を使う。プレビュー確定も別チャネルにせず、遅着release／cancelの再実行で支払い・効果・イベントをまとめて訂正する。通信中断は確定点へ戻してsimを停止し、実時間経過で拘束・転送・CTを進めない。新epochへ旧押下／解放を持ち越さない。

## HUDと表示・確定イベント

継続表示はstateから再構成し、音の一度だけ提示はM3-1のConfirmedEvent経路を使う。最小の追加イベントは次の2種とする。

```ts
{ kind: 'skill-started'; at: number; player: PlayerId; slot: SkillSlot;
  skill: 'trap' | 'chain' | 'energy-bolt'; position: Vec3 }
{ kind: 'skill-impact'; at: number; player: PlayerId; slot: SkillSlot;
  skill: 'trap' | 'chain' | 'energy-bolt'; target: PlayerId; position: Vec3;
  outcome: 'stun' | 'pull' | 'transfer' | 'blocked' }
```

startedは支払い確定時（trapは配置、他2種は予備動作開始）に1回、impactは選んだ敵との接触時に1回出す。適用できなかった接触はblockedであり、理由別の汎用効果ログを追加しない。弾が外れた時や物の期限切れはイベント不要、stateから表示を消す。スキルとoutcomeの組合せも受信で限定する（trapはstun／blocked、chainはpull／blocked、boltはstun／transfer／blocked）。開始位置・接触位置はsimで確定し、表示側が当たりを推測しない。

| 表示 | 最小要件 |
|---|---|
| 本人のスキル枠 | 設定済み主副、コスト、CT、設置中「離して設置／通常攻撃で取消」、busy・shared-wait・地点不可等の短文。既存skill-rejectedは本人の該当枠へ一度だけ提示 |
| 設置プレビュー | 本人だけに地面の円と斜線。純粋な地点計算と同じ半径・範囲・供給除外を表示する。合法領域だけを設置可能として示し、範囲外に偽の合法円を置かない。候補なしは理由文字を出す |
| トラップ予兆／起動 | 全員に床の歯形の輪郭と斜線、0.5秒の起動進行。起動後は輪郭を残し、警告中と線模様で区別する。薄暗さ・flash=0でも読める |
| chain／bolt予兆と飛行 | 保存射線を示す短い腕元の鎖形／菱形輪郭を0.3秒表示。鎖は細い節線、ボルトは菱形の先端と短い尾とし、丸い通常球・球種色・LCD顔をコピーしない |
| 拘束と耐性 | 本人HUDと人物の名札に「スタン」「引き寄せ」と残り時間。耐性は切れた鎖印、二人側の共有待機は両人の枠に残秒。正の残り時間を0秒と表示しない |
| 転送球 | 本物のコアを1個表示し、細い破線軌道と「転送中」の表示を添える。転送先は供給位置。通常球の輪郭・顔と危険時計を維持し、手元や供給位置に複製を置かない |

予兆の輪郭と位置は予測stateへ即応して訂正できるようにする。設置成功・発動・命中音は確定イベントを通し、stateの出現検知で鳴らさない。trapは機械的な短いラッチ音、chainは節の擦れる音、boltは短い電子音とし、通常球のcatch／parry／hitの打撃音と分ける。blockedを拘束成功音にしない。転送中央は既存crossingの確定音と輪郭を使い、転送完了音のためのイベントは増やさない。

新イベントもM3-1の一度だけ提示、300ms超の古い一時演出の省略、非表示・停止・旧ラウンド・再接続履歴の消費規則へ入れる。消えた予兆を遅い音に合わせて復活・延長しない。音なし・flash=0でも状態輪郭と文字を残す。skill-rejectedにSE／VFXは付けず、スキル成功にもヒットストップ・画面揺れ・全画面フラッシュを新設しない。球保護は0012の既存方針を使い、画面空間マスクは追加しない。

## Botと実装の分割

M3-4でもBotはアクティブskillを使わなくてよい。予兆回避AI・スキル選択・専用CT・直接state操作を追加しない。Botが拘束・転送を受ける時は人間と同じsim規則である。思考が出した不成立入力を拘束終了後へ予約しない。対戦条件の再現は通常Command列を使う。スキルを使わないBotとの試合を二人の交互拘束・視認性・対戦バランスの検証済みにはしない。

実装は次の2単位に分ける。各単位で資料の条件を振る舞いテストへ写し、未実装によるRedを実行確認してからGreenへ進める。

1. **sim・通信**：型・初期化・入力／受信検査・PROTOCOL → previewと配置 → 共通拘束と共有待機 → chain／bolt → transferと同時刻境界 → 保存・再実行・中断復帰。主にC16-2〜31、34を担当する。既存のgame側fixture等も新しい必須形式へ揃えるが、表示UIは同時に変更しない。設計書へ実装結果を追記する時は、この予定から区別する。
2. **入力結線・表示**：主副の押し離し・取消、復帰時cancel、プレビュー、予兆・飛行・拘束・転送、HUD、確定SE／VFX。主にC16-1、32〜33、35〜37と統合を担当する。simの判定・時刻を表示で二重実装しない。実装済みの0015入力・カメラ変更と統合してから画面を確認する。

単位1でK14・V15・K9・R01〜R10・既存通信再実行／再接続、単位2でS13とF12も回帰する。各単位の関連試験、`npm.cmd run check`、`npm.cmd test`、`npm.cmd run build`を行う計画である。sim・通信統合後はnetbenchの確定一致・不変条件を確認する。人間の試遊・別端末／実回線・TURN・性能評価は自動成功と区別して残す。

## C16 受け入れ条件

以下はすべて予定・未実施である。「一致」は同じ環境で同じ確定時刻のstateとeventsの一致を指す。±1は1/60,000秒の1時刻単位であり1Fではない。IDごとの複数条件は個別ケースへ分けてテストに写す。

| ID | テストへ写す条件 |
|---|---|
| C16-1 | 既定E/R・再割当主副で押下1回、ORの最後の解放でrelease1回。repeat・他方だけの解放で追加なし。即時型とPPの解放は無処理。blur／Esc／捕捉解除／設定適用はreleaseではなくcancelで、設置・支払いを生じない |
| C16-2 | 同時刻の状態入力を先に採用し、既存全行動順位を維持する。primary＋releaseは所持なら投球、非所持ならparryを試し、通常攻撃不成立でも設置は取消。同時cancel、同枠押下＋解放、枠1＋枠2、重複入力を配列順交換しても同一結果 |
| C16-3 | 各action、control、play／result／over、danger有無、KO、所持有無で3種の発動ゲートを検査。feintは成功時だけ解除。catch-whiff救済なし。拒否された入力は終了後に発動せず、支払い・CT不変 |
