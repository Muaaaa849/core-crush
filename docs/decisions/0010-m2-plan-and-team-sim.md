## ① 参加者と陣を分ける

### 状態と初期化

```ts
type PlayerId = 'p1' | 'p2' | 'p3' | 'p4';
type Side = 'a' | 'b'; // aは+z側、bは−z側
type MatchMode = '1v1' | '1v2' | '2v2';
// 初期化の入力。所属と能力は試合中に変更しない。
type Participant = { id: PlayerId; side: Side; stats: Stats };
// PlayerStateへ追加
lockTarget: PlayerId | null;
```

- `createInitialState({ participants, firstBall }, config)` に統一する。participantsは2〜4人、ID重複なし、各陣1〜2人で両陣が存在することを初期化時に検証し、不正な構成はエラーにする。能力は全員分を明示して渡す。画面の既定は攻撃・防御・敏捷すべて5。
- 人数形式は参加者から分かるのでsim状態へ別のmodeや生存人数を重複保存しない。PlayerStateの配列はID昇順で保持し、参照はIDで行う。KOしても要素を削除しない。試合中の所属変更はない。
- `owner`・`attack.target`・入力のplayer・個人イベントはPlayerId。`danger.side`・`ball.side`・`throwerSide`・`firstBall`・`wins`・勝者はSide。HP・資源を陣のキーで引かない。陣の符号判定と`opposite`はa/bへ統一する。
- ローカル操作者・ボット・接続相手はsim外でIDに対応付ける。ネットの接続IDをPlayerIdにしない。試合開始時にホストが参加枠を決める。
- 旧シグネチャ、旧Side、旧fixtureの補完は残さない。呼び出し元・テスト・HUDを新仕様へそろえ、移行・二重実装は作らない。ECS・任意人数向けのチーム管理層は不要。

### 初期配置と供給

各陣の人数とID順から配置を決める。s＝aなら+1、bなら−1。y＝0、yaw＝aは0、bはπ（yaw 0は−z向き）。キャラ範囲・判定形状・球速は0005／0006のまま。

| その陣の人数 | キャラの足元（x, y, z） | 球の供給位置 |
|---|---|---|
| 1 | `(0, 0, s × 7.8)` | `(0, 0.325, s × 7.8)` |
| 2 | IDの小さい順に `(-s × 2.6, 0, s × 7.8)`、`(+s × 2.6, 0, s × 7.8)` | 同上。人数で供給位置を変えない |

2人の陣では中央の球へ歩くか召喚して開始する。供給時の所有者は決めず、0009の回収条件を適用する。初球の陣だけを画面／ホストで抽選し、simへ値で渡す。全員ロード後の3秒カウントはsim外、球出現から1秒後の操作・時計開始はsim内。次ラウンドは0008どおり結果3秒→初期化・球出現→1秒後開始で、追加の3秒カウントは入れない。

### 1v2のHP

`maxHp = (100 + 6 × (防御 − 5)) × 補正`。開始時に1人対2人の1人側だけ補正1.6、それ以外は1.0。防御5なら160対100＋100、defense1なら121.6。整数へ丸めずHP全快で始め、just回復3%も補正後maxHpから求める（160なら4.8）。表示だけ小数1桁以内へ整える。

maxHpは試合中固定。2v2の味方KOで生じた1v2でも補正せず、次ラウンドも開始時の参加構成を使う。コスト最大5・初期1、ステップ最大／初期2、防御受付W、攻撃・敏捷は補正しない。両陣を入れ替えた1v2もsimで扱い、画面の初期選択は単独側を人間とする。

### 資源・爆発・勝敗・落球

- ステップ回復は各生存者が独立して積む。球のある陣が自分のsideと異なり、dangerが動いている間だけ回復。味方2人が同時に回復でき、回復時間を分配しない。KO・球なし・開始演出・result／over・通信中断は進めない。敏捷5の15秒、満タン時の余剰破棄は維持。
- 爆発はその陣の生存者全員へ1人30ダメージ。単独側にも30。旧球は1回だけ消し、逆陣への供給予定は1件だけ。0009どおり全員のactionを解除する。HP0の相手にさらに報酬や被弾イベントを作らない。
- 一方に1人でも生存者がいればKOだけでラウンドを終えない。両陣全滅は引き分け。時間切れ180秒は `チーム残HP合計 / ラウンド開始時のチームmaxHp合計`。KO者も分母へ含め、同率は引き分け。例：単独80/160と2人側100/200は同率。比率の比較は交差積で行い、同値へ独自の許容幅を足さない。
- 同時刻のダメージを処理してから1回だけ勝敗を確定。2勝先取・引き分け時の同番号再試合・供給陣の交代を維持する。リセットは全員の配置・HP・資源・action・yaw・ロック。move／keysは0008どおり押下状態を保持し、止まった時間に実行する行動を蓄えない。
- 0009の落球・ノックバックは個人へ適用する。回収は球と同陣の生存者、hitstun以外、高さ≦0.80m、水平距離≦1.20m、絶対60Hz境界。最短水平距離の二乗、同値ならID順で1人だけが取得。負けた候補のaction・資源は変えない。
- 同時刻の召喚はID昇順で評価し、最初の成立者だけコスト1を消費する。召喚成功なら同時刻の自動回収はない。先のIDが不成立なら次を評価する。爆発同時なら誰も消費・取得しない。
- 味方同士の押し合い・体による遮蔽・フレンドリーファイアはない。生存する味方は重なれる。KO者の移動・接触・防御・回収は無効、ロスターからは削除しない。

## ①② ロックと投球

### 画面中心をsimでどう表すか

画面の肩位置・FOV・pitch・揺れを判定へ渡さず、論理yawからの水平角で「中心に近い」を定義する。平面上の敵方向dに対し、前方f＝`(-sin(yaw), -cos(yaw))`、右r＝`(cos(yaw), -sin(yaw))`、角度＝`abs(atan2(dot(d,r), dot(d,f)))`。初期化・次ラウンド・対象KO時だけ、全生存敵を「角度→水平距離の二乗→固定ID」で並べて先頭を選ぶ。敵なしならnull。水平距離0なら角度0とする。

背後の敵も選択候補には含む。視点を動かすだけではロックを変えず、範囲外表示で振り向く必要を伝える。①ではこの自動選択と投球条件を先に作り、②で明示切替を追加する。

### Qのコマンド（R09）

- `Command`へ `{ kind: 'cycle-target'; player; at; seq }` を追加。生存敵をID昇順で巡回し、末尾の次は先頭。現在のロックが無効なら上記の初期選択だけを行う。敵1人なら同じ相手、敵なしならnull。リングはM2の候補に入れない。
- Qは押下1回で1コマンド、キーリピートは送らない。操作開始後の生存者が使え、球の所持・投げ始め・防御・hitstun・爆発後の待機には依存しない。ラウンド開始前、result／over、KO中は受け付けない。
- 選択の変更は資源も行動枠も使わず、フリを解除しない。move／keys／yawを先に反映し、次にQ、次に既存の行動優先順位、最後にrelease／接触を処理する。同時刻のQと投球・跳ね返しなら変更後の相手。Qが複数ならその人のseq順で適用する。
- コマンド順の基準は `(at, PlayerId, seq)`。seqは各参加者内で単調増加、別人と値が重なってよい。行動優先は個人ごとにステップ＞キャッチ＞跳ね返し・投擲＞フリ＞召喚で、配列順や通信到着順から決めない。

### 発射条件と飛行中の対象

| 場面 | 決定（初期案） |
|---|---|
| 通常投球 | 投げ始め8F後、同時刻のQ・yawを反映して、生存するロック敵が水平±80度以内なら発射。±80度を含み、既存防御と同じ1e-12 radだけ計算誤差を許す |
| 対象が範囲外／不在 | windupを終了し保持のままactionなし。release・投球後硬直・資源消費なし。自動で別の敵へ投げない。時計は継続。開始時の範囲だけでは拒否せず、8F中に振り向ける |
| 通常の跳ね返し | 防御成功者自身の接触時ロックへ返す。球種はその人のkeys、攻撃値・危険倍率・ラリーもその人から計算する。元の投げ手に固定しない |
| 跳ね返し時にロックが正面外／不在 | 入射の防御成功を取り消さない。論理yaw正面へ追尾なしのストレートを返す。対象なしの狙い投げと同じ直撃規則・速度を使う。球種keysはこの場合だけ使わない。成功報酬・ラリー加算は1回。背面への自動追尾を禁止しつつ防御条件を増やさないための補足細則 |
| 狙い投げ | ロックも敵の正面条件も不要。発射方向は論理照準、追尾なしのストレート。M2の平面simでは現行どおりyaw方向。上下の照準・ADS表示全体の追加は別スライスの課題で、今回の狙い投げ判定はsimコマンドで検証する |

BallAttackの`target`は`PlayerId | null`とする。通常投球・通常返球は発射時のID、狙い投げと上記の正面への非追尾返球はnull。`homing`とは別の意味であり、`homing=false`だから全敵に直撃できるとは解釈しない。通常球のステップ解除後もtargetのIDは維持し、進路へ戻ったその人だけに当たる。

飛行中のQやyawでattack.targetを変えない。対象KOならその時刻にhomingだけ解除し、直前の速度で進み、0009の最初の床・外周接触で攻撃を失う。KO者を追わず、別の生存者へtargetを差し替えず、nullにも変えない（全敵へ当たる球に化けるため）。白線外で解除されたら攻撃消失をその時刻で処理する。所有者ではない他人のQ・ステップはその球の追尾へ影響しない。

選択のKO更新と飛行対象の失効は同時刻のダメージ後に処理する。既に全滅でラウンド終了なら球を止める。現在の1球・スキルなしでは飛行中の対象だけが別要因でKOする場面は限られるが、保存状態からの失効も同じ規則に統一する。

## ② カバーと同時解決（R10）

### 接触候補

- 攻撃者の陣は`attack.throwerSide`を使う。`ball.side`は球の所在・時計用なので、中央を渡った後の敵味方判定には使わない。
- 防御候補はthrowerSideと異なる陣の生存者全員。対象以外の味方も、同じカプセル・受付時間・入射の正面160度でキャッチ／跳ね返しできる。カバー専用ボタン・追加半径・報酬倍率は設けない。
- 直撃候補はtargetがIDならその生存者だけ、nullならthrowerSideと異なる陣の生存者全員。非対象の体は通り抜け、有効防御だけが止める。狙い投げは最初の敵1人に当たって落球し、貫通しない。
- 接触は0005の掃引カプセルを使う。各等速区間で、直撃時刻と、有効な防御受付区間との最初の交差時刻を求める。非対象が重なったまま防御受付へ入るなら受付開始時に接触する。無効な防御・非対象の単なる重なりは事象候補にせず、時刻0の接触を繰り返さない。
- 次事象に防御の`startsAt`も含め、入力・移動境界・誘導更新・受付境界で候補を再計算する。算出時刻は1/60,000秒へ一度だけ切り上げ、同じ整数なら同時扱い。候補より早い別事象で状態が変われば古い候補を使わない。

### 一つの攻撃球を一度だけ処理する

1. 最も早い接触時刻まで進め、既存の爆発→入力・行動境界→中央通過を処理する。爆発で球が消えたらその旧球の候補はすべて捨てる。
2. その整数時刻の**成立する防御**を、球中心と各人の防御点（足元＋高さ1.20m）の3次元距離の二乗→IDで並べ、先頭の1人だけを確定する。元の対象・キャッチ・跳ね返しに参加者間の特別な優先権はない。同時刻の直撃より有効防御を先に扱う。
3. 有効防御がなければ、その時刻の直撃候補から同じ距離→IDで1人だけに命中させる。通常球には候補が最大1人しかいない。
4. 成功時だけ球をheld／新しいflight／looseへ置き換える。報酬・回復・ラリー・hitはその処理で1回だけ。敗れた防御者には成功報酬も成功硬直も与えず、元の受付・空振りへ進む。新しい返球へ旧候補を流用しない。
5. 未所持球の境界更新・回収と対象KOの整理を終えてから、チーム勝敗を1回だけ確定する。同時刻の床・外周への攻撃消失は、その旧球で防御／直撃が成立しなかった場合だけ行う。

tick終了境界の接触は次tickへ渡して同時刻の入力を待つ（0009）。その前に時間切れ勝敗を確定しない。新しい返球の接触は最短でもrelease＋1時刻単位（約0.017ms）から探索し、発射位置の重なりで同じ時刻に球を往復させない。これは1Fの受付追加ではない。飛行・所有は常に1球で、隠れた「処理済み」集合をsim外へ置かない。

## ボット・画面・最小UI

### 味方にも敵にも同じBotを使う

①では既存の球種巡回（直球→左→右→上、4回に1回フリ）、保持から1.5秒後に投球する練習Botを人数分使う。敵は`id !== self.id`ではなく異なるsideから選び、lockTargetへyawを向ける。自陣looseには、回収可能な生存者のうち球に最も近い人（同距離はID）だけが寄る。人間もこの比較に含め、他のBotはその場でmove＝0にする。回収可否のhitstunを外し、保持・追跡終了・ラウンド変化で古いmoveを残さない。初期位置へ戻る経路探索は作らない。

②では非対象のBotによるカバーを追加する。味方が狙われたflight中に非対象Botは味方の2m手前（球側）の点へ歩き、コート内へクランプする。自分への現在の等速掃引の予測接触が3〜6F先なら入射へyawを向け、1飛行に1回だけ防御入力を出す。成功／不成功を問わず試行ごとにキャッチ→跳ね返しを交互にする。2v2は各陣2人なので役割割当の管理層は不要。通常対象のBotはM1どおり防御しないため、無限に完全防御する相手にはならない。追尾の未来や人間の未送信入力を読ませず、カバー失敗も許す。試遊前の人間のカバー確認は別途必要。

Botはsimの公開状態から通常コマンドだけを出し、位置・HP・球を直接書き換えない。①②のsim再実行テストには生成済みコマンド列を使う。③でホストを巻き戻す際には、Botの保持開始時刻・投球回数・防御試行等の内部状態もホストの履歴へ保存・復元して再思考する。クライアントではBotを動かさず、ホストのBot入力を使う。

### 人数選択

開始オーバーレイへラジオ3個「1v1（既定）」「1v2（自分1人対ボット2人）」「2v2（味方ボット1人）」と既存の「プレイ開始」を置く。ローカルはp1固定、その他の参加者だけをBotにする。

| 選択 | a陣 | b陣 |
|---|---|---|
| 1v1 | p1：あなた | p3：Bot |
| 1v2 | p1：あなた（HP1.6倍） | p3・p4：Bot |
| 2v2 | p1：あなた、p2：Bot | p3・p4：Bot |

開始後は人数変更不可。Escはマウス解放のみで試合を止めない。ローカルの5秒後再戦は選択した同じ人数で全員とBotの記憶を初期化する。人数を変える最小操作は再読み込みして選び直す。URL設定・保存・チーム入替UI・難易度設定は追加しない。③以降のオンラインでは5秒のローカル自動再戦を使わず、全員の結果確認後に部屋へ戻す。

### HUDとカメラ

- アバターを参加者分生成し、位置補間も配列番号でなくIDで対応付ける。p1/p2の固定2体、勝者IDとlocal IDの比較を廃止する。HUDの勝敗は`winner === localPlayer.side`。
- 味方／敵の見分けはside、名前は「あなた」「味方 P2」「敵 P3／P4」のようにID付き。全員のHP/maxHpとKO、チーム勝ち数、危険な陣、自分の資源を表示する。残HP割合の分母からKO者を消さない。
- ロック名と枠を常時表示し、正面外なら「対象が正面外」。飛行中の対象マークはattack.targetから描き、Qで動く選択枠と形を変える。自分宛てと味方宛ての球を判別でき、nullの球は対象枠を付けない。
- 生存中のFPS/TPSはローカルIDだけを基準に0007〜0009を維持。味方が保持しても自分のFPSへ移らない。自分がKOし味方が生存なら、その味方へTPS観戦を切り替える。操作IDは移さず、観戦者の向き・Q・攻撃を味方へ送らない。全滅なら結果表示。
- 次ラウンドで自分へ戻し、Controlsのyaw／送信済み状態もsimの初期yawへ同期する。補間・遮蔽物処理・被弾姿勢の追従先も観戦先へ合わせ、判定位置やロックを表示側から書き換えない。
