| 層 | 所有するもの | 持ち込まないもの |

| 通信 | 入力の認証・順序、100ms受付、ホストの再実行、完全状態と確定イベント、ロスター合意、復帰 | 表示側の音やVFXによる成否決定、クライアントの成功申告 |

スキルは入力からsimで成立させ、必要な状態を完全スナップショットへ含める。同一環境・状態・入力・configからstateとeventsを再実行一致させ、全端末はホスト確定へ従う。ブラウザ間の浮動小数点のビット一致保証は追加しない。設置プレビューは表示だけだが、配置の合法性・コスト消費は確定入力でsimが再検査する。幻影の描画も表示側だが、予約消費・本物の球種・最短着弾制約はsimである。

## M3-1：イベントから演出への対応

新しい「成功」「警告」等のSimEvent種別は作らない。既存イベントへ、発生後の状態から復元できない事実だけを必須フィールドとして追加する。時刻は既存の整数単位、位置はsimのワールド座標を複製する。表示用の色・長さ・音名はsimへ入れない。

| `parry` | 現在は`at/player/grade`。`position: Vec3`と`rallySpeed: number`を追加。位置は返球へ置換する前の`ballContactPoint`、ラリー値は今回の加算・上限適用後 | 評価別の金属SE、外向き火花・薄い輪、判定文字、既存ヒットストップ。ラリー値で音の高さを小幅に上げて飽和 |

## M3-1：表示時刻とオンラインの確定

### 一回の結果を一回だけ提示する

1. ローカルは`SimRunner.drainEvents()`の結果を確定結果として受け取る。オンラインはホスト自身もクライアントも`MemoryClient.events`の連続した確定列だけを受け取る。予測のstate差分・`predict()`・再実行中のeventsから成功音、判定文字、ヒットストップ、結果VFXを発火しない。
2. オンラインの提示識別子は`matchId + ConfirmedEvent.seq`とする。現在の実装は復帰後も同一試合の履歴を引き継ぐため、epochだけで消費位置を0へ戻さない。epochは受信の有効性に使う。状態パケットの`eventTail`が先着しても、通常受信では実イベントを消費した扱いにしない。欠番は既存のネット層で埋める。
3. `OnlineMatch`から表示へ渡す時にも連番を保持する形へ整理する。旧`SimEvent[]`形式との二重APIは残さず呼び出し元を更新する。ローカルは試合生成単位とdrain順の連番で十分であり、simへID採番を追加しない。保存するのは消費済み末尾と短い未提示キューだけとし、全試合分の再生済み集合を増やさない。
4. 通信中断・完全再同期では短命演出を消し、渡された履歴末尾までを消費済みにする。復元された履歴を新規に鳴らさない。新matchId／ローカル再戦で消費位置を初期化する。無効試合・退出では全キューと音声ノードを解放する。勝敗やHPの復元は確定状態の仕事で、演出の省略によって失わない。

### 接触と再生開始

表示用に`displayNowMs`（単調な表示時刻）と`viewSimAt`（描いている状態に対応するsim時間軸上の時刻）を区別する。ローカルの位置補間はpreviousとstateの間なので、`viewSimAt = previous.now + alpha × (state.now − previous.now)`を同じ補間率から求める。補間値には端数があってよく、整数のsim状態・イベント時刻へ書き戻さない。オンラインは現在の表示で`alpha=1`なので予測state.nowに対応する。sim時刻を音声時計と直接足し合わせない。

- ローカルは`viewSimAt >= event.at`となる最初の描画で演出を開始する。tick内のイベントを補間された球より先に鳴らさない。表示更新で複数tick進めた場合も時刻順に消費する。
- オンラインは上の条件と確定受領の両方がそろった最初の描画で開始する。出来事は通常既に過去にある。現在の人物へ位置を付け替えず、イベントに保存した発生位置へ出す。過去の接触へ球・カメラを巻き戻して合わせる処理は作らない。
- 音・VFX・判定文字・ヒットストップは同じ採用結果と開始時刻を使う。WebAudioはその描画で取得した`AudioContext.currentTime`から直ちに短い包絡を開始し、VFXの年齢は0から表示msで進める。ヒットストップでVFXの寿命や警告間隔を止めない。
- 発生から`viewSimAt`までの遅れが300msを超える短命結果演出は、消費済みにして鳴らさず描かない初期案とする。300msちょうどは提示する。勝敗HUD・確定ログ・統計は捨てない。別ラウンドに持ち越された短命演出も省略する。省略件数と遅れを検証ログに残す。
- タブ非表示では音を止め、短命演出をためない。復帰・音声再開時に過去の音をまとめて鳴らさない。Escはオンラインsimを停止せず、メニューを開いただけで確定列を巻き戻さない。

ここでいうfeel.mdの「接触0ms」はローカルの表示接触が基準である。オンラインは確定待ちが加わり、100ms受付に通信・tick・配送待ちが乗る。確定音を入力反応p95 50msと同一の指標へ混ぜず、イベント時刻→提示・予測接触→確定提示を別計測する。遅いと感じる可能性を承知した設計案であり、快適さを保証する値ではない。許容できなければ試遊記録を基に資料から見直し、予測音へ無断で戻さない。

### 警告は継続状態から作る

警告の区間キーは`matchId + danger.side + danger.expiresAt`。初期案は経過7.00／7.25／7.50／7.75秒の4区間で、各区間につき短音1回、8秒以降は0回。表示msを累積して危険時計を別に作らない。

ローカルは現在のdanger、オンラインは最新の確定stateで存在を確認できたdangerを使い、`viewSimAt`との差から経過を求める。オンラインで予測側のside/expiresAtが一致しない、球が消えた、試合がplay以外、通信中断なら鳴らさない。予測の通過は警告を止める方向にだけ使い、新しい警告区間の開始を確定前に認めない。警告は成功の通知ではなく、その時点で保持している危険状態の通知である。

フレーム飛びで複数区間を越えたら現在の区間を1回だけ提示し、過去分を追い鳴らししない。一度消費した区間は訂正で戻っても再生しない。中央通過／爆発／ラウンド変更／復帰で古い区間を破棄し、将来の警告音を事前予約しない。音声未開始・ミュート・非表示中の区間も消費し、再開時にはその後の新しい区間から鳴らす。本人の陣は高め、敵陣は低めの二音で区別する初期案とし、位置音だけに時計の意味を依存させない。

## M3-1：WebAudio合成SE

外部音源ファイル・音声依存は追加しない。ブラウザのWebAudioだけで、発振器・短いノイズバッファ・フィルター・Gainの包絡から作る。音色表を通常データとして持ち、`kind/grade/rallySpeed/敵味方`から波形・周波数・長さ・相対ゲインの記述へ変換する部分は純粋関数にする。ノイズは固定seedで作った短い共有バッファを表示側で一度生成する。simの乱数や状態には影響させない。

下表の周波数・長さは初期案。音量の数値だけで明瞭さを保証しない。既存SEがないため、比較試聴で採用音色を決める。

| SE | 合成方針 | 長さの初期案 |
|---|---|---|
| 跳ね返しso-so | 400〜700Hzの鈍い芯と低域を残す短いノイズ | 90ms |
| 跳ね返しgood | 900／1450Hzの非整数倍の金属的な芯、100Hz付近の軽い低音 | 100ms |
| 跳ね返しjust | 1400／2300Hzの鋭い芯、80Hz付近の低音、短い高域ノイズ。音量だけでgoodと分けない | 110ms |
| キャッチ | 高域を落としたノイズと500→200Hzの下降音。評価で芯の明瞭さを変える | 120ms |
| 被弾 | 低域ノイズと160→60Hzの下降音。金属的な成功音の芯は使わない | 160ms |
| 爆発 | ごく短いノイズの立ち上がり、破裂成分、80→35Hzの低音。1イベント1組 | 240ms |
| 警告 | 自陣は880→1320Hz、敵陣は660→880Hzの短い二音 | 合計70ms |
| 中央通過 | 帯域を狭めた上昇音。成功SEより控えめ | 70ms |

ラリーによる跳ね返しの音高は`1 + 0.15 × clamp(rallySpeed / rallySpeedCap, 0, 1)`を初期案とし、音量を積み増さない。敵側の成功音は芯の音高を少し下げ、発生位置の左右パンと併せて区別する。カメラの論理位置・右方向からパンを求め、画面揺れを混ぜない。初期パン範囲は±0.7、距離減衰はコート内の重要音が無音にならない範囲に留める。

同時発音は8音の初期案。満杯なら最古の音を短い減衰で止めて置換する（優先度の段階は作らない。試聴で問題が出たら足す）。マスターゲインに上限を設け、各音は短い立上り／終端の減衰を持つ。上限制御をしてから試聴し、割れや不快な高音がないか確認する。

AudioContextは一つだけとし、明示的な「プレイ開始」またはオンラインの「操作する」操作で作成／resumeする。開始前の音を蓄えない。失敗・suspended時は音声を開始できていないことを表示し、同じ明示操作で再試行する。別音声方式へのフォールバックは作らない。ミュート時も画面の状態表示と試合は動作する。停止・退出・非表示では短い減衰で止め、終了ノードをdisconnectする。

M3-1にはSE音量／ミュート、揺れと閃光の0設定を確認できる最小の操作を置く。永続化・全設定画面はM3-6へまとめ、その時点で一つの設定経路へ統合する。色収差・モーションブラー・BGM・環境音はM3-1に追加しない。

## M3-1：VFXと文字の寿命・上限

three.jsの線分・薄いリング・小さな半透明面で作る。Effekseerは候補のままとし、M3-1では採用・比較実験を必須にしない。汎用パーティクルエディター、物理破片、追加ライトは不要である。形状と材質を共有し、最大数が決まった小さな表示枠を再利用する。

| 要素 | 寿命の初期案 | 同時上限の初期案 | 規則 |
|---|---|---|---|
| 火花群 | 120ms | 4群、1群8本、計32本 | so-so／good／justで3／5／8本。被弾は4本。接触点から外向き、中心へ戻さない |
| 衝撃輪・キャッチ輪 | 160ms | 4枚 | 跳ね返しは拡張、キャッチは収束。ただし球の外縁より内側へ潰さない |
| 爆発局所閃光 | 80ms | 1枚 | 球消去位置の近傍だけ。白い全画面フラッシュは禁止 |
| 爆発破片 | 220ms | 1群、12本 | 物理・衝突なし、外向き線分。衝撃輪は上記の共通枠を使う |
| 中央フェンス波紋 | 180ms | 2枚 | 通過点中心、半径最大1.2m。薄い輪だけを広げる |
| 被弾外周 | 120ms | 1枚 | 初期範囲は画面端から12%以内、不透明度最大0.25。同時被弾でも加算せず更新 |
| 判定文字 | 450ms | 1枠 | JUST／GOOD／SO-SO＋行動・人物。本人の結果を優先し、同優先なら最新で置換。勝敗表示とは別枠 |

全体上限は上表の合計以下とし、毎フレーム期限切れを取り除く。新規要求は種類別の最古を置換する。火花は超過分を出さない。割当数を増やして解決しない。優先的に省略するのは装飾の火花・破片で、判定文字・球・時計の表示は維持する。被弾と爆発の揺れが重なる場合も加算せず大きい方を一回採用し、初期上限は既存justと同じ5cm／120msとする。

### 球の輪郭を最優先する

- 画面空間の保護範囲・線分ごとの交差判定は作らない（親の判断、KISS）。代わりにワールド空間で次を守る。
- 火花・破片は小さい線分で、球中心から球半径＋0.1m以上離れた位置から外向きに出す。輪は線だけで内部を塗らず、内径を球半径＋0.1m以上に保つ。キャッチ輪の収束もこの内径で止める。
- VFXは深度を書き込まず、不透明な板を置かない。全画面ブルームの強度をイベントで引き上げない。被弾外周は画面端12%以内だけ。
- 判定文字はレティクル下の固定枠に出す。球へ追尾させない。
- 評価は文字と輪の形・動きでも示す。チームは人物名・IDと音色でも区別し、色だけに依存しない。揺れ0で評価情報を失わない。閃光0でも輪と文字を残す。
- この規則だけで「読める球」の合格にはしない。高速ラリー、キャッチFPS切替、爆発直後、2v2の重なりを実画面で確認し、隠れる場面が見つかったら規則を足す。

## M3-1：実装単位と検証

クラス階層やイベントバスは作らない。既存の実行器→main→表示の流れに、小さな演出用データ変換と出力を足す。ファイル名は実装時に整理してよいが、責務は次の単位で保つ。

| 単位 | 内容 | 検証方法 |
|---|---|---|
| 事実の追加 | simイベントへ発生位置・ラリー値を保存、受信検証を更新 | 接触・爆発・通過の境界、保存復元のstate/events一致 |
| 演出計画の純粋関数 | イベント→音色・輪・火花・文字の記述。視点人物・設定・configを引数で受ける | 同じ引数で同じ記述。イベント／stateを変更しない |

| 出力 | 記述からWebAudioノードとthree.js表示を更新。投影範囲の交差判定は数値で分離 | API呼出しや寿命は偽時計で確認、音色と最終表示は実ブラウザ |

最初はイベントの追加と対応表、次に一度だけ提示する経路、その後にSE、VFX／文字の順で小さくRed→Greenを行う。音色・寿命は表示側に一か所だけ定義し、simのconfigへ演出値を混ぜない。既存HUDの成功メッセージと新しい判定文字、既存ヒットストップと新しい演出で同じ通知を重ねない。

## M3-2：キャラ定義とロスターの概要

正本の能力・2枠はcharacters.mdの初期ロスター表とする。キャラID、表示名、攻撃／防御／敏捷、2枠のスキルID、配色を一つの小さな定義表で管理する。共通モデルとモーションは共有し、キャラ別GLBを複製しない。スキルIDの列挙はロスター表示に必要な範囲だけであり、汎用の効果言語は作らない。

HPをキャラ定義へ手入力しない。既存の`baseHp + defenseHpCoefficient × (defense − defaultStat)`へ、開始時の1v2単独側補正を掛ける。既存係数による初期案はVOLT／SWITCHが94、ECHOが106、ANCHORが112、1v2単独側はそれぞれの1.6倍となる。受付幅・歩行・球威・ステップ回復も既存の能力式から導く。資料・UIに別のHP表を権威として持たない。

ローカルは開始前に各参加枠のキャラを選べるようにし、Botも同じ定義を使う。オンラインは本人のキャラIDだけを部屋へ送り、部屋側が有効IDと参加枠を検査する。開始時に確定した全員のID・所属・キャラIDを全リンクで合意し、各端末は同じビルドの定義から能力を解決する。利用者が送った任意statsやHPは採用しない。現在の`localMatch(mode)`だけでオンライン全員を5/5/5に生成する経路を置き換える。通信の旧形式補完は作らない。

M3-2ではキャラ選択を部屋の既存フローへ足すだけとし、自由なチーム編集・Readyの全体整備はM4-3に残す。開始手続きに入ったらキャラを固定し、再接続では同じ枠・キャラ・最大HPを復元する。次の試合はその時の確定ロスターで初期化し、途中変更しない。正式ロスターの重複選択は禁止しない。
