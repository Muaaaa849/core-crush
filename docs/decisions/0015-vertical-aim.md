## 論理pitchと確定時刻

```ts
// 既存の at / seq / player を持つCommandへ追加する。
{ kind: 'pitch'; pitch: number }
// PlayerStateの必須フィールドへ追加する。
pitch: number;
```

pitchは上向きが正、単位はradである。yawと同じ独立した入力状態とし、primaryやskillへ角度・照準点・カメラ位置を添付しない。これにより投げ始め後のマウス移動と、M3-4の非所持中の照準も同じ契約で扱える。ADSしていない間も変化したpitchを送る。ADSのon/off自体は引き続きgame層の状態である。

- `aimPitchLimit = 1.2`をsim側の共通定数とし、controlsと通信検査も参照する。初期値を既存から引き継ぐ。ローカル操作は加算後に±1.2へクランプする。
- 受信Commandは有限number、範囲内（両端を含む）、既知のフィールドだけを許可する。欠落・文字列・NaN・Infinity・範囲外・余分な座標を拒否し、通信入口で範囲外の値を丸めて受理しない。at/seq/playerの検査は既存どおりである。
- simの直接呼び出しでは有限値だけを反映して±1.2へクランプする。非有限値は状態を変えない。ネットワークの拒否を代替する処理ではなく、simが非有限状態を作らないための境界である。
- 角度は浮動小数のままとし、量子化・小数桁丸め・送信閾値を追加しない。時刻だけ既存の1/60,000秒単位を使う。量子化は現在のyawにもなく、本スライスで帯域圧縮は行わない。
- 同時刻はmove/keys/yaw/pitch → Q → 行動 → リリース・接触の順である。同じ人の同時刻のpitchは既存のseq昇順で反映し、最後の値が残る。yaw/pitchの相互の到着順は方向を変えない。
- pitchはyawと同じstate入力であり、windup・硬直・フリ・KO・開始待機・結果中でも記録する（overでは既存どおり処理しない）。pitch変更だけでフリをキャンセルしたり、行動枠を消費したりしない。

**投げ始めで確定するのは狙い投げかどうかだけである。** primary.aim=trueをwindupに保持し、途中のADS解除では通常投球へ変えない。発射位置・yaw・pitch・照準点・最終方向はリリース時、同時刻の状態入力を反映した後に確定する。終了tick境界のリリースは次tickの同時刻入力を待つ。投球後の視点変更で飛行済みの球を曲げない。

通常投球は既存のリリース時keys・Q・水平正面条件で追尾球種と対象を決め、pitchを軌道へ加えない。狙い投げはkeysにかかわらずstraightである。対象不在・正面外への非追尾返球も従来の水平yaw直球を維持する。`launchBall`のreceiver=null全体にpitchを掛ける実装にしてはならない。狙い投げの呼び出しだけが明示的な発射方向を渡す。

初期状態・次ラウンド・新しい試合のpitchは0とする。復帰は0初期化ではなく確定stateのpitchへ戻す。controlsのsyncはyawとpitchを一緒に復元し、両方の送信済み値を無効化する。通常の予測訂正のたびに手元の視点を確定stateへ戻す処理は追加しない。

## 共通照準点と実際の発射方向

### カメラの肩位置を入力にしない

**論理的な目からレティクル先の点を選び、球は発射位置からその点へ飛ばす。FPS/TPSは同じ点を見る。** 肩越しカメラのforwardを球へコピーする方式は採らない。近距離では肩の横ずれだけでレティクルと弾道が外れ、feel.mdの共通照準点の要件を満たさないためである。

論理的な目は、FPS/TPSやADSにかかわらず本人の足元位置Pから`E = P + (0, aimEyeHeight, 0)`、初期案`aimEyeHeight = 1.60m`である。球の発射位置は既存の`M = P + (0, defenseHeight, 0)`、高さ1.20mである。表示上の手・保持球の右下オフセット・アニメーションをMに使わない。

論理視線の単位方向を次で計算する。

```text
D = (-sin(yaw) cos(pitch), sin(pitch), -cos(yaw) cos(pitch))
T = E + D × 照準距離
発射方向 = normalize(T - M)
```

pitch=0は目からの水平視線を意味する。目と発射位置に0.40m差があるため、球のvyが常に0になる意味ではない。上下限は論理視線のpitchへ掛ける。視差補正後の発射方向を再度±1.2へクランプしてTを外してはならない。

### 点Tの最小限の決め方

リリース時点のsimの幾何から、Eを始点とするD方向の半直線について次の候補の最短の正距離を求める。未来の移動・追尾・先読み補正は使わない。

1. 生存する敵の縦カプセル表面。球半径を加えず、既存`capsuleRadius / Bottom / Top`を使う。既存の`sweptCapsuleContact`へ速度D、受け手速度0を与えれば、返り値を距離として使える。本人・味方・KO者は候補から外す。
2. 床y=0と、白線の物理位置に対応する垂直4平面（x＝±(ballHalfWidth+r)、z＝±(ballHalfDepth+r)）。rは試合球半径である。これは照準点を選ぶ平面であり、実際の球中心の衝突範囲とは区別する。床上の点は白線矩形内、側面上の点は残る水平軸が白線範囲内かつy≧0のものだけを候補とする。高さ上限と中央平面は候補にしない。
3. 初期案`aimMaxDistance = 60m`の遠点。より近い候補がなければこの点を使う。これは照準用の距離であり、弾の寿命・射程・速度制限ではない。

`aimEyeHeight`と`aimMaxDistance`はSimConfigへ追加し、既存のsession署名で双方の一致を検査する。表示側にも同じconfigを渡し、game層に別の目の高さ・遠点距離を重複定義しない。

同じ距離の候補から得るTは同じなので、照準対象IDを保存しない。0以下・非有限の交差距離は候補外である。現在の両陣の移動範囲ではEが敵カプセル内になることはない。カプセル拡大による吸着、画面上の敵への補正、Q対象の優先を加えない。見た目のモデルではなく論理カプセルの表面を狙う契約である。

Tは視線の先にある静的な一点であり、球がTへ到達した後も同じ速度で飛行する。敵の移動で外れれば追い直さない。別の敵がM→Tの途中へ入れば、通常の全敵接触候補でその敵に当たる。

### 表示への接続

表示側も同じ純粋計算でTを求める。ローカルの最新yaw/pitchと表示用の位置群を使い、FPS、TPS、100msの切替中のすべてで、既存の位置リグからTへlookAtする。TPSの肩位置・後退量を決める基底にはDを使い、補正後のカメラforwardを再入力しない。カメラの位置補間だけを残し、補間中もTが画面中央に投影されるようにする。

表示位置の補間と通信予測によるTの差は表示側だけの誤差である。simは常にリリース時の論理位置から再計算する。FOV、画面比率、レティクル設定、画面揺れ、カメラ補間率をsimへ渡さない。揺れは論理カメラを置いた後の演出であり、論理射線へ逆流させない。照準点の奥行を別途平滑化してsimと異なる狙いを作らない。レティクルは中央の1個を維持し、予測着弾点の別マーカーは追加しない。

## 壁越し発射と白線の境界

Tの探索に成功しても発射経路が通行可能になったわけではない。**実際の接触はMから始まる半径付きの球で判定する。** カメラやEを球の開始点にせず、Tへ瞬間移動しない。床・外周の消失時刻はMと最終方向から既存`attackLossAt`で計算し、Tの向こうまで攻撃判定を通さない。

現行simに、球が衝突するケージのポリゴン・小物・遮蔽物の一覧はない。床と白線の垂直境界だけを球の遮蔽境界とする。中央フェンスは攻撃球が通れる世界観であり、射線を遮らない。ステージメッシュへのthree.js Raycasterや任意障害物の新規登録をsimに持ち込まない。「壁越しなし」の受け入れは、この現行の論理境界について検証する。

白線外にいるキャラの狙い投げは、Mが最初から球中心の許可範囲外なので、リリース時刻で攻撃を失いlooseへ移る。白線の境界上も既存の`attackLossAt`どおり即消失し、内向きの発射でも例外を作らない。Mをあらかじめ白線内へ動かして発射する処理は作らない。リリース・投球後硬直・オーバーチャージの支払いは成立した手投げとして通常どおりである。落球位置は0009どおり白線内へ寄せる。

カメラだけが白線の外・反対側にあっても、Mが内側ならMからの有効射線を使う。カメラの見通しだけで発射可否を決めない。照準用の細い線が敵を捉えていても、球半径のため先に床・外周へ触れればそこで攻撃を失う。

## 飛行・高さ・球速

狙い投げは**重力なしの等速直線**とする。新たな放物運動、空気抵抗、途中のpitch更新は追加しない。直撃または床・外周でlooseへ移った後だけ、0009の重力9.8m/s²と反発・減速を使う。追尾解除後の球は解除直前の3次元速度を維持し、投げ手の現在pitchへ向け直さない。

球速は既存のstraight基本値・能力・危険時間・ラリー・強化・総上限を使い、`max(minimumBallSpeed, rawLaunchSpeed(...))`とする。現在の基本値36.4m/s・下限6.5m/sを維持する。下限は水平成分ではなく3次元速度の大きさである。

**対象なしの非追尾投球には最低飛翔時間による速度制限を新設しない。** 現行`launchBall`はreceiverありの静止受け手までの軌道長だけを使って240/270/320msへ制限する。照準点までの距離をその代わりに使うと、床・遠点・敵へのカーソル移動だけで球速が変わる。本書ではrules.mdの最低飛翔時間を、その既存の追尾投球・追尾返球の計算として具体化する。狙い投げと対象なし返球は、近距離で240msより早く当たりうる。狙い投げにも反応猶予を保証する企画変更は本スライスに混ぜない。追尾球の下限6.5m/s優先規則も維持する。

**新しい上限高さは設けない。** 非追尾の白線外周は高さ無制限の垂直境界であり、上から越えて外へ抜けることはできない。現行simにケージの天井判定はなく、照明・トラス・金網の見た目を新たな天井にしない。高く投げた球は最初の床・外周接触、人物への接触、または危険時計の爆発まで進む。外周より先に上昇した球を一定高さで水平へ曲げたり、床へ落としたりしない。

従ってケージの見た目より高い飛行・高い位置からの落球は起こりうる。これは既存の上限なしを維持する決定であり、見やすさの検証済みを意味しない。高所滞在中も危険時計は進み、召喚は既存どおり自陣のlooseなら高さを問わず使える。高所の球が読みづらい場合は、試遊結果を根拠として別途上限高さ・表示を判断する。未検証の天井高さを実装者が独自に足してはならない。

## 接触・中央通過・危険時計

`flightPosition`、`sweptCapsuleContact`、`ballContactPoint`は既に3次元であり、その幾何を再利用する。直撃・キャッチ・跳ね返しの判定形状は同じカプセルのままである。球半径を加えた合成半径0.625mを使い、頭上を通る球を水平距離だけで当てない。

防御は受付時間と**水平**の正面160度を維持する。受け手のpitchで上下の防御範囲を狭めない。±1.2radの通常の狙い投げには水平成分があるが、既存の水平速度0を防御不可とする判定も変えない。上下を向くだけでキャッチが失敗する新ルールは作らない。接触時のkeys/Qで返球する規則・同時防御の距離とID順・1球1結果・ノックバックの水平成分も維持する。

**攻撃中の中央通過と、looseの中央反射を分ける。** 床・白線外周への最初の接触で攻撃を失う。中央では攻撃を失わず、球中心のz=0到達で陣と8秒時計を更新する。中央を床・外周と同じ攻撃消失面にしてはならない。looseになった後は中央から半径分離し、以後は同じ陣で反射する。

同時刻は既存どおり、爆発 → 入力・行動境界・リリース → 中央通過 → 有効防御 → 直撃 → 攻撃消失 → looseの物理・回収 → 勝敗である。床・外周と人物接触が同じ整数時刻なら既存の防御・直撃優先を維持する。各幾何時刻は一度だけceilし、終了境界のpendingContactsも保存する。消失時に`dropBall(..., 'loss')`を使い、入射水平成分の20%・上限5m/s、vyの20%・±3m/s制限と、該当境界の反発を引き継ぐ。直撃時は`'hit'`の初速を使う。

- 高さを問わず、攻撃中の中央通過で受け側の時計を0へ戻す。期限ちょうどなら爆発が先である。
- 上を狙っても白線の外へ先に達すれば、その時点のball.sideでlooseになる。中央より前なら自陣に残り、時計は戻らない。
- 中央通過と外周消失が同じ整数時刻なら、先に中央通過した後の陣へlooseを置く。過去の0009の規則を維持する。
- 落球後の床・外周・中央反射、回収、召喚、照準の変更では時計を更新しない。射線探索のTが相手陣にあるだけでは中央通過にならない。

## 保存復元・通信・入力の再開

PlayerState.pitchを必須として、初期state・完全state・保存複製・途中再実行・同期・再開・完了snapshotへ含める。受信stateのpitchは有限かつ±1.2以内を要求する。欠落を0で補完する互換処理は作らない。古いstate・fixtures・Command検査は新形式へ統一する。既存データを削除する作業ではない。

Tや論理的な目はstateに保存しない。windup中はその時点のstateからリリース時に再計算でき、飛行中は既存のorigin・velocity・segmentOrigin・segmentAtが確定方向を保存する。画面やカメラをホスト再実行に必要な依存にしない。

入力配送はyawと同じ再送・seq重複排除・100ms未確定区間・予測訂正を使う。後から届いたpitchが受付可能なら、ホストは該当時刻から再実行してリリース方向を訂正する。確定済み・遅すぎる入力は既存どおり拒否する。angleだけを別チャネルへ出さない。

再接続のHeldInputはmove/keysのままとする。yaw/pitchは同期された確定stateから復元し、中断中のローカル視点変更・未確定の照準を新epochへ持ち越さない。復帰時のcontrols.syncを明示的に接続し、yaw/pitchの再送キャッシュを無効にする。ラウンド変更だけを検出して済ませない。再開先頭がwindup終了境界でも、同期stateと同じ角度から処理できることを検証する。通常のメニュー・blurによるreleaseAllはADSと押下を解除するが、論理pitchは消さない。

**PROTOCOLは3から4へ上げる。** 必須stateと受理Commandが変わり、同じ見た目の入力でも新旧simの結果が異なるためである。room-protocol、Worker・クライアントの検査、session合意、関連fixtureを同じ版へ揃える。設定の保存形式は変えず、設定versionは上げない。旧版の部屋・stateとの互換経路、pitch欠落のフォールバックは追加しない。実装時に別の形式変更が先行していた場合は、その時点のPROTOCOLから次の版へ統合して上げる。

## BotとM3-4への再利用

Botの思考・snapshot/restore形式は変更不要である。初期pitch=0のまま通常追尾球を投げ、追尾軌道はpitchから独立する。狙い投げ・上下追尾・新しい防御思考をBotへ追加しない。既存カバーの3次元接触はそのまま使う。ただし、Botが狙い投げに防御しない現状を、人間も防御できない根拠にはしない。

共有するのは、plain dataを受けて`{ origin: M, target: T, direction }`を返す**射線計算だけ**である。配置候補は`src/sim/aim.ts`であり、three.js・DOM・描画dt・カメラモードをimportしない。入力は足元位置、yaw、pitch、同時点の照準候補となる敵の位置と生存状態、必要なconfigで足りる。球種・速度・ダメージ・CT・行動優先・イベント配送は持たせない。

M3-4のエナジーボルトとチェーンは同じM/E/Tの計算とpitch入力を使う。ADSしていないTPSでも同じTが中央へ投影される。予備動作がある弾は実際の射出時に最新のyaw/pitchから射線を確定する方針を引き継ぎ、具体的な発生時間・中断規則はM3-4で定める。

弾半径、球速、寿命、命中効果、防御可否、ステージ境界は各スキルの設計事項である。試合球の半径・最低飛翔時間・危険時計・loose化をスキルへ自動適用しない。照準点の選択は共通、最初の実接触はそれぞれの発射位置・判定幅で評価する。汎用Projectile、効果フック、弾種登録表は今回作らない。
