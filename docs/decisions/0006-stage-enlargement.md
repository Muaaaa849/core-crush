# 0006 ステージ1.3倍拡大と球速の再調整

- 日付：2026-10-07
- 状態：採用（企画変更、ユーザー指定「ステージと球を約1.3倍、球速も調整」）
- 出典：GPT-6 Astraへの設計相談（読み取りのみ）を親が整理

## 拡大の方法

ステージGLB全体を拡大・伸縮するのではなく、D:/T3test の生成スクリプトをゲーム側（`scripts/assets/arena/`）へ複製し、寸法を指定して再生成・再組立する。原本（D:/T3test）は変更しない。

| 部材 | 方法 |
|---|---|
| 床（`build_arena_floor.py`） | デッキ22×39m、白線コート13×31.2m（片側13×15.6m）で再生成。白線は独立メッシュ `arena_floor_low_lines`（材質 `MT_line_paint`）で、線幅0.1mは維持。補助線は奥行±5.2／±10.4m、円は中心±7.8m・半径1.95m。床UVの3m周期は維持 |
| 金網（組立） | `CAGE_X=10.5, CAGE_Y=18.0, MOD=3.0`。短辺7部材（中央がゲート）、長辺12部材、角4。部材は原寸で共有 |
| 中央プラズマフェンス（`build_plasma_fence.py`） | ケージ幅まで延長（柱中心間20.3m、カーテン幅19.6m）。柱・高さは原寸、模様は伸ばさない。再ベイク |
| トラス（`build_light_truss.py`） | 9m部材で再生成。組立の `TRUSS_Y=(-8.45, 0, 8.45)`、高さ8m、スポット12灯 |
| 小物・ボード・背景 | 原寸。小物は新しい余白へ再配置。都市背景・外周床は位置も大きさも維持 |
| ライト | 既存の光量・角度を引き継ぎ、照射先だけ新コートへ。three.jsの1/683補正は維持 |

生成順：床 → フェンス → トラス → 組立（他の部材は原本GLBを読む）。出力は `.cache/arena/`、配信用は従来どおり `npm run assets` で `public/assets/stage.glb` へ。

## 球と速度

| 項目 | 旧 | 新 |
|---|---|---|
| 球の直径（見た目＝判定） | 0.5m | 0.65m |
| 基本速度 ストレート／左右／上 | 28／23／17 m/s | 36.4／29.9／22.1 m/s |
| 総速度上限 | 基本×1.6 | 維持 |
| 最低飛翔時間 | 240／270／320ms | 維持 |
| 球速下限 | 6.5m/s | 維持 |
| 歩行・ステップ・防御タイミング・8秒 | — | すべて維持 |
| カプセル（受け手） | 半径0.30m、軸0.30〜1.50m | 維持（球との合成半径は0.625mへ） |

到達時間は標準距離どうしでほぼ同じになる（目安：ストレート約483ms、左右約620ms、上約875ms。実装後にsimで旧新を比較して確定する）。フェイント：標準距離でストレート約29F、再投擲8F＋発生8Fと合わせて約45F＜キャッチ空振り54F（余裕約9F）で、旧来の関係を保つ。

歩行は1.3倍にしない。敏捷10で7.475m/sとなり球速下限6.5m/sを超え、R03の保証が崩れるため。

## R03（歩行で避けられない）の条件

最大歩行5.75m/s＜球速下限6.5m/s。キャラの移動範囲は誘導範囲の内側（各辺0.075mの余裕）。0.65Lで曲がりを終えて純粋な追尾、誘導更新0.05mを維持。保証するのは「歩行だけでは追尾を切れない」ことで、8秒以内の必着ではない。無効方向ステップ中（約14m/s）は距離が一時的に開きうる（0005の記述をこの意味に整理）。

## カメラ

変更しない（後方2.2m、肩0.5m、FOV 90度）。球径と標準距離が同じ比率で増えるため、標準距離での球の見かけの大きさはほぼ同じ。遠くの相手は小さく見えるので、2v2のロック表示で補う。

## 受け入れ条件

- 素材：`stage.glb` の金網配置がx=±10.5m、z=±18mに並び、白線メッシュの外形が13×31.2m、1ファイル25MiB以下（`tests/assets.test.ts`）。
- sim：新寸法・新球径・新速度で既存の受け入れテストが通り、静止相手への到達時間の順序と最低飛翔時間、白線外の相手への命中、R03の歩行パターンが成り立つ。
- 画面：コート・ケージ・フェンスの見た目と移動範囲が一致する（ユーザー確認）。性能は feel.md の基準で再計測する。
