## M3-2：定義表と境界

`src/game/characters.ts`に依存の少ない定義表を置く。three.js・DOM・通信・保存APIはimportしない。workerも同じ表をimportしてIDを検査し、別の許可ID一覧を手書きしない。型の初期形は次とする。

```ts
type SkillId = 'overcharge' | 'blink' | 'phantom' | 'boost-ring'
  | 'chain' | 'charge' | 'trap' | 'energy-bolt';
type SkillDefinition = {
  name: string;
  kind: 'active' | 'passive';
  status: 'unimplemented'; // M3-2時点。効果を実装するスライスで更新する
};
type CharacterDefinition = {
  name: string;
  stats: Readonly<Stats>;
  skills: readonly [SkillId, SkillId];
  colors: { base: string; emissive: string }; // #RRGGBB
};
// CHARACTERSは下表4件のオブジェクト。表のキーからIDを導く。
type CharacterId = keyof typeof CHARACTERS;
type RosterEntry = Readonly<{
  id: PlayerId;
  side: Side;
  characterId: CharacterId;
}>;
type Roster = readonly RosterEntry[];
```

`CHARACTERS`は`as const satisfies Record<string, CharacterDefinition>`、スキルの表示表は`Record<SkillId, SkillDefinition>`で検査する。スキル名・種別・未実装状態は1か所に置く。まだコスト・CT・効果関数・汎用効果言語は作らない。PP試験キャラとバックライン封鎖は正式4キャラの選択肢へ入れない。

| ID／表示名 | 攻撃／防御／敏捷 | 枠1／枠2 | 基本色／発光色（初期案） |
|---|---|---|---|
| `volt`／VOLT | 7／4／4 | `overcharge` オーバーチャージ／`blink` ブリンク | `#D8A52A`／`#FFE27A` |
| `echo`／ECHO | 4／6／5 | `phantom` ファントム・スロー／`boost-ring` ブーストリング | `#8067B5`／`#CBB4FF` |
| `anchor`／ANCHOR | 4／7／4 | `chain` チェーンハンド／`charge` 蓄勢（パッシブ） | `#68856F`／`#B4D6A0` |
| `switch`／SWITCH | 5／4／6 | `trap` スクラップ・トラップ／`energy-bolt` エナジーボルト | `#BB7657`／`#FFD0A0` |

共通モデル・骨格・モーションを共有する。基本色は衣服・装甲の共通材質へ乗算し、発光色は小さなキャラ識別部へ使う。肌・顔・球・チーム識別へ一括着色しない。材質の色値は人物ごとに分離し、ある人物の変更で別人の色が変わらないようにする。キャラ別のGLBやモーションは複製しない。

チーム色は表示側の`Side`別定数に分け、初期案はA=`#57C7FF`、B=`#FF718A`とする。名札の縁と足元のチーム印へ使い、キャラの基本色を置き換えない。敵味方はローカル人物の所属との比較で求める。球種色・選択ロック枠・飛行対象マークは既存規則を保つ。

### 能力の解決と開始ロスター

`src/game/match.ts`でID昇順のロスターを検査し、`characterId`から`Participant.stats`を複製して`MatchOptions`を作る。ローカルとオンラインが同じ変換関数を使う。未知ID・重複PlayerId・形式と異なる人数／所属はエラーとし、VOLTや5/5/5で補完しない。キャラID重複は合法である。

M3-2のsimは既存の`Participant { id, side, stats }`を維持する。表示用の名前・色・未実装スキルをsim状態へ混ぜない。開始ロスターはローカル試合の所有者とオンラインの`Session.roster`が不変値として保持し、HUD・Bot生成・アバターへ同じ値を渡す。ネットの保存復元ではsessionとstateを組にし、表示がstate配列の位置や端末の現在選択からキャラを推測しない。M3-3で効果に必要な情報だけsimへ追加する。

HPは定義表へ持たず、既存configとsimの式から導く。初期係数なら基礎maxHpはVOLT／SWITCH=94、ECHO=106、ANCHOR=112。開始時1v2の単独側だけ1.6倍、justキャッチ回復は補正後maxHpの3%、時間切れ分母はKO者も含む開始時maxHp合計である。能力による球速・受付・歩行・ステップ回復も既存式を使い、HP・受付・速度の別表をUIへ手書きしない。算出値を表示するときだけ丸める。

### ローカルの最小UI

開始画面の人数選択の下に「自分のキャラ」の4択を置く。既定はVOLT。キャラ名・3能力・2枠の名前と未実装状態を示し、選択結果から参加者一覧を即時更新する。M3-2では選択の永続化を追加しない。

本人はp1・A陣のまま、Botは**参加枠固定**でp2=ECHO、p3=ANCHOR、p4=SWITCHとする。存在しない枠は生成しない。本人の選択や乱数でBotをずらさず、本人とBotが同じキャラでも許可する。3形式の構成は次のとおりである。

| 形式 | A陣 | B陣 |
|---|---|---|
| 1v1 | p1：本人の選択 | p3：ANCHOR |
| 1v2 | p1：本人の選択、maxHp補正を併記 | p3：ANCHOR、p4：SWITCH |
| 2v2 | p1：本人の選択、p2：ECHO | p3：ANCHOR、p4：SWITCH |

開始で一覧を固定する。次ラウンドと5秒後のローカル再戦は同じロスターを使い、Bot内部状態だけ従来どおり初期化する。選び直しは開始画面へ戻った時に行う。開始画面へ戻る導線を増やさない段階では既存どおり再読み込みする。Botの思考・難易度・完全防御は今回変更しない。

### 名札と2枠

名札の本文を「関係・人物ID・キャラ名」に統一する。例は`あなた P1 VOLT`、`味方 P2 ECHO`、`敵 P3 VOLT`である。対戦前一覧にはさらに`A陣／B陣`、ローカルBotには`Bot`を付ける。頭上の名札とHUDのHP一覧・ロック名・飛行対象名は同じ名前生成を使う。KOは既存のKO表示を追加する。キャラ名だけで人物を識別しない。

開始画面と部屋の一覧に全員の2枠、試合HUD下部に本人の2枠を文字で出す。専用アイコン素材は必要としない。

- アクティブ例：`[E] オーバーチャージ — 未実装`。主副割当があれば両方を表示する。M3-2では既定E/R、M3-6以後は現在の設定から引く。
- パッシブ例：`常時：蓄勢 — 未実装`。E/Rの発動誘導やCT表示を出さない。説明は「実装予定：goodキャッチの獲得量増加」のように予定を明示する。
- 未実装は色だけでなく文字で示す。使用可能な点灯・予約・CT・消費を出さない。M3-2ではE/Rによる効果もパッシブ効果も0とする。

## M3-2：部屋申告・開始合意・復帰

### 部屋の変更点

`src/net/room-protocol.ts`の`RoomPlayer`へ必須`characterId`を足す。ロビーでも全員が有効IDを持つ。初回作成・参加は開始画面の選択を必須で送り、無指定の旧要求を受理しない。

| 経路 | 要求と処理 |
|---|---|
| 作成 `POST /rooms` | `{ mode, build, characterId }`。形式・buildの構文・キャラIDを作成枠消費前に検査する |
| 新規参加 `POST /rooms/:code/join` | `{ build, characterId }`。部屋のbuild一致、ロビー、空席、有効IDを検査後に枠を作る |
| トークン付き復帰 `POST /rooms/:code/join` | `{ build }`。保存済み枠を返す。キャラ再申告を認めず、余分な`characterId`は拒否する |
| ロビー内選択 WebSocket | `{ kind: 'select-character', characterId }`。送信者はsocketの認証済み`info.id`から取る。`id`・`side`・`stats`・HP等の余分なフィールドを拒否する |

`worker/logic.ts`に本人枠の選択更新を置く。更新は`phase === 'lobby'`だけとし、有効IDなら永続化・全員へ`RoomView`を配信する。同じIDの再選択は同じ結果でよい。`worker/index.ts`ではロビー用メッセージを試合の`matchId`検査より前に振り分ける。現在の`/init`は後続のjoin用入力をbuildだけで作り直しているため、作成者の`characterId`も失わず渡す。

`room.ts`は作成・新規参加・選択変更に選択IDを渡す。UIは申告中を示し、部屋から戻った値を確定表示する。本人以外の変更操作は置かない。開始手続き中・カウント中・試合中は選択を無効にし、手作り要求もworkerで拒否する。`select-character`と`begin`はworkerの処理順で決まり、beginより後の変更は次のロスターへ紛れ込ませない。

### 開始合意

1. ホストの既存`begin`で全員の接続・人数を検査する。各枠の有効IDを再検査し、`connecting`へ移した時点の`players`を固定する。新matchIdと初球の陣は従来どおり部屋が決める。別の編集用／試合用ロスターをworkerへ二重保持しない。
2. 各端末は受信したbuildが自身の`__BUILD_ID__`と一致すること、形式どおりのID・所属・有効キャラIDであることを検査する。`RoomPlayer`から`loaded/confirmed`を除いたID昇順の`Session.roster`を作り、同じ変換関数から初期stateを生成する。オンラインの`localMatch()`流用を削除する。
3. 既存`OnlineMatch.signature()`のcanonical sessionに`roster`を含める。署名対象はmatchId、初期epoch、build、protocol、config、ロスター、初球を反映した初期stateである。これで同能力・別キャラも区別する。ユーザーの感度・音量等は含めない。
4. 必須素材の準備と全スターリンクの接続完了後、各参加者が既存`loaded { matchId, signature }`を送る。workerは本人枠ごとの署名を比較し、全員一致後だけ3秒カウントへ進む。ホストも1枠として比較する。追加の合意用DataChannel往復やロスター専用ハッシュは作らない。
5. 不一致・不正ロスター・準備失敗・20秒期限では開始せず、理由を表示して既存abortでロビーへ戻す。ロスター選択は保持し、`loaded/confirmed`と署名だけ解除する。利用者のReadyと`loaded`を同一視しない。

ビルドIDは既存のsrcと素材を含む生成値を使い、手入力のキャラ版番号を増やさない。定義表はsrcに置くため能力・配色・スキル表示の変更も検出される。異なるbuildは新規参加・トークン付き復帰とも拒否する。受信形式変更ではM3-1後の`PROTOCOL`から更新し、旧形式を補完しない。新形式を持たない保存部屋も明示的に利用不可として新規作成を案内し、自動移行・既存保存データの削除は行わない。

### 再接続と再ラウンド

接続トークンは既存sessionStorage、部屋のロスターはworkerの既存永続化に保持する。設定用localStorageへ参加権限やロスターを移さない。保存Admissionは接続の手掛かりであり、復帰時の正式な枠・キャラはworkerのRoomViewから取る。

同じmatchIdでロスターを変えず、再ラウンドでも初期maxHpと能力を保持する。復帰は既存の完全state／確定イベント／新epochの同期を使い、HPを全快にした初期stateで上書きしない。`Session.initial`を中断状態へ置き換える既存restartでも`Session.roster`は維持する。

進行中に同じmatchIdのRoomViewを再受信しても、`loaded/confirmed`等だけを更新し、保持する開始ロスターを書き換えない。ID・所属・キャラが異なれば不整合として停止する。再読込したクライアントはworkerの固定ロスターからsessionを再構成し、ホストから現在の確定stateを受け取って初めて復帰する。

通常snapshot・sync・resume・completeの受理時に、参加ID集合・所属・stats・maxHpが開始ロスターから決まる値と一致することを検査する。HP現在値・行動等の可変値との比較はしない。不一致は復帰成功にせず無効試合として理由を出す。KOを理由に参加枠を消したり1v2補正を付け替えたりしない。確定状態を失ったホストの再読み込みは従来どおり無効扱いであり、ロスターだけから試合を復元しない。

全員の結果確認後にロビーへ戻ったら選択変更を再び許可する。次のbeginで新matchId・新しい開始ロスターを作る。途中参加・Bot置換・ホスト移譲は追加しない。

## M3-6：一つの設定経路

`src/game/settings.ts`に現在形式の型・既定値・純粋な検査を置き、保存読込は同ファイルの小さな関数で行う。`controls.ts`は検査済み設定から物理入力を行動へ変換する。設定画面は同じ実行時設定を更新し、controls・カメラ・レティクル・M3-1の出力がそれを読む。設定用イベントバス・汎用UI生成器・プロファイル切替は作らない。

開始画面とEscメニューから同じ設定画面を開く。編集は下書きで行い、「適用」で一括反映・保存、「キャンセル」で破棄する。「既定に戻す」は下書きを既定値へ戻し、適用するまでは保存しない。オンラインはメニュー中も試合が進むと明示する。

### 主・副の2割当

物理入力は`{ device: 'keyboard', code: string }`または`{ device: 'mouse', button: 0 | 1 | 2 | 3 | 4 }`、割当は`[主 | null, 副 | null]`とする。キーボードは`KeyboardEvent.code`相当の物理位置で保持し、設定画面にも`KeyW`等を確認可能にする。主副は優先度ではなく同じ行動の別入口である。既定の副はすべて空とする。

対応codeはKeyA〜Z、Digit0〜9、Arrow4方向、Space、Tab、Enter、Backspace、Delete、Insert、Home、End、PageUp、PageDown、ShiftLeft/Right、Backquote、Minus、Equal、BracketLeft/Right、Backslash、Semicolon、Quote、Comma、Period、Slash、IntlBackslash、IntlRo、IntlYen、Numpad0〜9、NumpadAdd/Subtract/Multiply/Divide/Decimal/Enterとする初期案である。保存検査と捕捉UIは同じ許可表を使い、その他は「未対応」、後述の予約キーは「予約」と区別する。配列レイアウトの自動取得やIME中の入力捕捉は行わない。

| 行動ID／表示 | 有効な所持状態 | 既定主 | 変換 |
|---|---|---|---|
| `forward/back/left/right`／前後左右 | 両方 | W/S/A/D | 移動と球種用`keys` |
| `step`／ステップ | 両方 | 左Shift | `step` |
| `summon`／球召喚 | 両方 | C | `summon`。成立可否はsimが決める |
| `cycle-target`／ロック切替 | 両方 | Q | `cycle-target` |
| `throw`／投球 | 所持 | 左ボタン | `primary`、ADS有効なら`aim: true` |
| `parry`／跳ね返し | 非所持 | 左ボタン | `primary` |
| `ads`／ADS | 所持 | 右ボタン | 押す／切替のローカル状態 |
| `catch`／キャッチ | 非所持 | 右ボタン | `secondary` |
| `feint`／投げるフリ | 所持 | F | `feint` |
| `skill1/skill2`／固有枠1／2 | 両方 | E/R | 行動IDまで。効果への接続はM3-3以降 |

有効な所持状態は、ローカル操作人物が`ball.mode === 'held'`のownerかどうかで決める。FPS/TPSの補間率や観戦対象で切り替えない。生存・操作捕捉・メニュー・通信中断の入力抑止と、simの硬直判定は別である。所持でもキャッチ動作中なら投げられない既存規則を維持する。

各行動は主副のORで押下中かを求め、false→trueで1回だけ押下を出す。主を押したまま副を押しても追加発動せず、両方を離すまで解除しない。キーリピートも新しい発動にしない。所持状態が変化しただけで、押し続けている共有キーから新しい行動を生成しない。状態を跨いだボタン行動は一度離してから押し直す。移動は状態を跨いでも連続する。

移動の符号は`forward = 前 − 後`、`right = 右 − 左`とする。主副を2本押しても1方向は1であり、速度を倍にしない。移動はyawでワールドへ回転・正規化し、球種用`keys`は回転前の同じ符号を送る。上下相殺・左右相殺の後、後<0なら上カーブ、右<0なら左カーブ、右>0なら右カーブ、それ以外はストレートとする。

例：前I・後K・左J・右LならK+Jは上、I+K+Jは左、J+Lは直球となる。旧WASDを別途参照しない。設定画面に押下中の方向と結果球種の小さな確認欄を置き、試合へは入力を送らない。

マウス／キーの押下をCommandへ変換する前に、その時点の方向とyawの変更を送る。同じ時刻では既存simのkeys／yaw→Q→行動の順を維持し、同一描画フレーム内に方向キー→投球を押しても前フレームの球種にしない。返球は既存どおり接触時の最新keysを使う。

### 共用・競合・予約キー

2行動の有効な所持状態が交わらなければ同じ物理入力を共用できる。投球と跳ね返し、ADSとキャッチは合法であり「所持／非所持で共用」と表示する。移動等の共同行動との重複、同じ状態の2行動への割当は競合とする。硬直中に使えない、現キャラがパッシブ、まだ未実装という理由では競合を免除しない。

競合する行動名・主副・有効状態を文字で表示し、黙って片方を優先しない。下書きで次を選べる。

- 交換：選択した割当欄の旧入力と、唯一の競合欄の入力を入れ替える。全体を再検査し、新しい競合が残るなら実行不可。複数欄との競合では交換を出さず理由を示す。
- 上書き：選択欄に新入力を置き、重なる状態の競合欄をすべて空にする。排他的な合法共用は残す。
- キャンセル：下書きを変更しない。同一行動の主副へ同じ入力を登録する操作も受理せず、既登録と示す。

全戦闘行動は少なくとも主副の片方が必要である。上書きや解除で両方が空になった行は「未割当」と示し、競合または未割当がある下書きは適用しない。E/Rの未実装行もこの検査に含め、スキル実装後に突然操作不能になる保存を作らない。

入力捕捉は1個のキーまたは対応マウスボタンに限定し、キーの組合せを1割当として保存しない。左Shift等の単独修飾キーは許可する。Ctrl・Alt・Meta単独とそれらを含む入力、Esc、F1〜F12は予約として割当不可にする初期案である。例としてCtrl/Cmd+Rの再読込、Ctrl/Cmd+Wのタブ終了、Alt+Tab、F11等を理由付きで示す。Escはメニュー・捕捉解除用で固定し、割当捕捉中は捕捉の取消とする。全OSの予約操作を捕捉できるとは案内しない。

通常プレイでもCtrl・Alt・Metaを含む入力を戦闘へ流さない。ブラウザが先に処理する操作を奪おうとしない。ゲームで受け取れるSpace・矢印・Tab等の既定動作は、プレイ中または割当捕捉中に必要な範囲だけ抑止する。フォーム・メニューの通常操作やページ全体には適用しない。マウスは0〜4だけを対象とし、ホイール・ジェスチャー・多段マクロは作らない。3/4等をブラウザが渡さない環境は副割当で操作し、実機の対応を別に確認する。

### 感度・ADS・FOV・レティクル

設定の初期形は以下である。すべて有限数・範囲内、booleanはboolean、列挙は指定値だけを受理する。範囲外を黙って丸めたり文字列の数値を受理したりしない。

| 設定 | 既定／範囲の初期案 | 適用 |
|---|---|---|
| `sensitivity.fps/tps/ads` | 各1.0、0.1〜5.0 | 使用モードの倍率を1個選ぶ |
| `sensitivity.x/y` | 各1.0、0.1〜3.0 | 共通の横／縦倍率 |
| `invertY` | false | pitchの増減だけ反転 |
| `adsMode` | `hold`、`hold/toggle` | 押している間／押すたび切替 |
| `fov` | 90度、70〜110度 | FPS/TPS共通の垂直FOV |
| `reticle.shape` | `cross`、`cross/dot` | 中央の十字／点 |
| `reticle.size` | 12、4〜24 CSS px | 十字全幅または点の直径 |
| `reticle.color` | `#FFFFFF` | `#RRGGBB`。暗い縁を常に付ける |

`deltaYaw = -movementX × rad(0.044) × モード倍率 × x`、`deltaPitch = -movementY × rad(0.044) × モード倍率 × y × (invertY ? -1 : 1)`とする。0.044度/countは現在の実装値を初期案として引き継ぐ。pitchの上下限±1.2radも維持する。感度に表示fps・deltaTime・FOVを掛けず、同じマウス量で同じ角度を得る。

モードはADS有効ならADS、そうでなければ論理的なFPS/TPSを使う。キャッチ動作中TPS・投球後硬直中FPSという既存の切替時刻へ合わせる。100msの表示補間の途中でも感度を補間しない。ADSの感度をFPS倍率と二重に掛けない。

ADSは本人が所持中でFPS操作が可能な時だけ有効とする。holdは主副のOR、toggleは押下エッジで切り替える。所持喪失・投球リリース・KO・ラウンドリセット・メニュー表示・blur・捕捉解除・通信中断・設定適用で解除する。キャッチキーを押したまま球を取得してもADSへ自動遷移しない。解除後は新しい押下を必要とし、toggle状態を保存しない。

ADS有効時の投球押下は既存`primary { aim: true }`へ変換する。投げ始めで狙い投げかを確定し、途中でADSを解除しても通常投球に変えない。射出方向の更新時刻はsimの規則に従う。ADS時FOVは`通常FOV × 75/90`の初期案とし、独立したADS FOV設定は増やさない。レティクルは常に中央、設定でロック名・飛行対象・必須HUDを消さない。

**上下照準の残件**：現在の`aim`はyaw方向の非追尾投球であり、縦感度とY反転だけを実装しても上下の射線は完成しない。M3-6の入力・設定と区切って、論理pitchのsim入力、発射位置からの3次元射線、床／壁・防御・再実行を扱う小スライスの設計が必要である。M3-4のボルトも同じ射線を使う。本書は表示pitchを送るだけの仮実装や水平投球との互換切替を追加しない。親が着手位置を決めるまで、上下照準を含むR11の最終達成は保留する。

### 演出強度とM3-1の統合

`effects { volume, muted, shake, flash }`を同じ設定オブジェクトへ持つ。初期案はvolume=1、muted=false、shake=1、flash=1。各数値は0〜1である。「演出」欄にSE音量、ミュート、揺れ、閃光を並べ、曖昧な一括強度から複数値を推測しない。

- volumeはM3-1の基準音量への倍率、mutedは有効音量を0にする独立値とする。ミュート解除で以前のvolumeへ戻る。警告音を含む全SEに同じ出口で適用する。
- shakeは既存ヒットストップの揺れ・被弾・爆発の表示変位への倍率とする。論理yaw/pitch、球、判定、ヒットストップの時間は変えない。
- flashは局所閃光と被弾外周の不透明度への倍率とする。0でも球・時計・顔・名札・判定文字・衝撃輪と必要な予兆を残す。背景を含む全画面ブルームの倍率へ流用しない。
- 適用は現在鳴っている音と残存する揺れ／閃光にも効く。0→1やミュート解除で終了済み音・VFXを再生しない。提示済み連番や警告区間を初期化しない。

M3-1の暫定操作と独立した音量状態・揺れ状態を廃止し、全呼び出し元をこの設定へ揃える。WebAudioの開始は既存の明示操作経路を維持し、保存値を読むだけで音声を開始しない。同時8音・最古置換、VFX寿命・上限、ワールド空間の球保護規則を弱めない。

### localStorageと失敗時の扱い

保存キーは`corecrush-settings`、値は`{ version: 1, bindings, sensitivity, invertY, adsMode, fov, reticle, effects }`のJSONとする。キーの1は形式識別であり移行機構ではない。設定は端末・ブラウザの同一origin内で共通とし、ビルドIDへ結び付けない。キャラ選択・参加トークン・試合state・現在の押下・ADSの切替状態は保存しない。

| 状況 | 動作 |
|---|---|
| キーなし | 既定設定で開始。警告は不要 |
| 読込成功・全項目有効 | オブジェクト全体を適用し、画面と入力・表示を同じ値にする |
| JSON破損、version違い、欠損・未知項目、不正な型／範囲／キー、競合・未割当 | 全体を不採用とし既定設定で開始。「保存設定を読み込めないため既定値を使用」と表示。部分補完・旧形式の移行はしない。保存値を自動削除・上書きしない |
| localStorageの取得／getItem失敗 | 既定設定で開始し、保存機能が利用できないことを表示。試合は開始できる |
| 適用時のsetItem成功 | 検査済み下書きを実行時へ適用して保存済みと表示 |
| setItem失敗 | 検査済み設定は今回のセッションへ適用する。「このセッションのみ適用。保存失敗」と表示。以前の保存値は削除せず、同じ適用ボタンで再試行できる |

下書き検査に失敗した場合は実行時設定も保存値も変更しない。保存を毎フレーム試みず、適用時だけ行う。保存失敗後の再読込は、実際に残っている以前の値または既定値から再開する。自動で別保存先へ切り替えない。別タブの変更を試合中へ自動反映する仕組みは作らない。

メニュー・blur・捕捉解除・設定適用時は物理押下集合とADSを解除し、移動／球種keysの0を通常入力経路へ渡す。通信中断なら現在保持入力を0へ更新し、復帰ACKへ古い移動を残さない。閉じるクリックや適用前に押していたキーを新割当の発動へ流用せず、プレイ再開後の新しい押下から扱う。

## 実装単位と親への引き継ぎ

M3-2は定義とローカル生成・名札 → 部屋申告と開始合意 → 復帰の順、M3-6は設定型と入力変換 → UIと保存 → ADS・感度・表示 → M3-1の暫定設定整理の順に小さく進める。各単位で資料を先に合わせ、上記条件のRed → 最小実装 → Green → 整理後の関連検証を行う。

実装時は`tests/game/`のmatch・controls・HUD・設定、`tests/sim/`の資源・人数・再生、`tests/net/`とworker試験の部屋・同期・再接続を対象とする。通信変更後はT10-25〜28・T10-32〜34の自動確認分、設定統合後はF12の一度だけ提示・停止・上限・sim不変を回帰する。最終確認は`npm run check`・`npm test`・`npm run build`。実回線・TURN・試聴・人間の視認性評価は別に未検証を残す。

親への未決事項は、上下照準の小スライスをM3-6の直後へ置くか、M3-4より前のどの区切りで行うかである。配色・感度範囲・FOVと演出倍率は本書の初期案で実装を開始できるが、試遊の調整値は未決定である。固有スキルの支払い・CT・同時入力優先等は0012どおりM3-3の詳細設計で閉じる。
