# 0009 被弾ノックバックと落球のバウンド・転がり

- 日付：2026-10-07
- 状態：採用（設計決定、実装・テスト・試遊は未実施）。被弾時の落球・ノックバック・バウンドはユーザー要件、数値と細則は初期案
- 出典：ユーザー指定「当てられてダメージを受けたときにボールを落とす」「キャラクターはノックバック」「ボールは物理演算的にバウンドして転がる」。将来、投げ・被弾・跳ね返し・キャッチのアニメーションを追加する

## 対象と方針

直撃が成立した球を、その場で床上の静止球にする処理から、攻撃判定のない未所持球の運動へ置き換える。現行は1球なので、落とすのは命中した球そのもの。別の保持球を作らない。HP・ラリー・危険時計・追尾中の接触判定は従来の規則を保つ。

汎用物理エンジンは入れない。キャラは等速の押し出し、未所持球だけ重力・床反発・水平減速で表す。床・白線外周・中央線以外の接触、キャラへの再衝突、角運動量、空気抵抗は持たない。0004・0005の攻撃中の解析的な時刻判定は維持し、落球後の運動と回収だけ60Hz境界で判定する。

## 被弾キャラ

| 項目 | 決定（初期値） | 理由 |
|---|---|---|
| 方向 | 命中直前の球の水平速度を正規化した方向。水平速度の大きさが0.000001m/s以下なら受け手の陣の奥向き（P1は+z、P2は−z） | 球に押された向きが分かり、真上からの球でも方向が一意になる |
| 距離・移動時間 | 1.4m／12F（0.2秒）、等速7m/s | ステップ2.8mの半分。被弾が見え、追い直しの距離を広げすぎない |
| 硬直 | 被弾から24F（0.4秒）。後半12Fはその場で停止 | 跳ねた球を即回収する挙動を防ぎ、短い立て直しを作る |
| 壁 | 既存のキャラ中心範囲（x±10.1m、各陣の奥行0.5〜17.6m）で成分ごとにクランプ | 金網・中央フェンスを越えず、斜めなら壁沿いの成分だけ進む |

- ダメージを受けてHPが残ったとき、既存actionを `hitstun` へ置き換える。ステップ移動、catch/parryの発生・受付、空振り・成功後硬直、投げ始め・フリをすべて中断する。以前の行動へ戻さず、消費済みコスト・ステップを返さない。
- `hitstun` 中は通常歩行と全行動（ステップ・投擲・防御・フリ・召喚）を不可とし、自動回収も不可。`move`・`keys`・`yaw` は記録する。視点は動かせるが押し出し方向は変わらない。行動入力は予約せず捨てる。24Fちょうどから最新の移動入力で歩行でき、新たな行動入力を受け付ける。
- 金網に当たって押し出し距離が短くなっても硬直は24F。壁への追加ダメージ・跳ね返り・無敵時間はない。
- 同時刻の防御・ステップ入力は既存の順序で先に評価する。有効防御なら被弾せず、無効防御やステップ中に直撃した場合は `hitstun` が優先する。
- 直撃でHP 0なら、その時刻にKOを確定しactionを消す。KO者のsim位置は動かさない。球は通常の被弾と同じ初速で落とすが、ラウンド終了なら0008どおりその場で球も停止する。倒れる動きは将来の表示だけで作る。
- 爆発はノックバック・落球を起こさず、旧球を消す。既存どおり全員のactionを解除するため、途中の `hitstun` も終了する。生存者は爆発後も歩行・ステップ可（0008）。同時刻なら爆発を優先し、その球の直撃は起こさない。

## 未所持球の運動

### 攻撃球からの切り替え

被弾時は接触した時刻の**球中心**を開始位置にする（`hit.position` の球表面上の接触点とは区別する）。高さは `max(球半径, 現在のy)` とし、床へ瞬間移動させない。x/zは下記の未所持球範囲へ寄せる。白線外のキャラに当たった場合の内側への移動は、従来の「小物の陰に球を残さない」規則を優先する。

| 項目 | 値・規則 | 理由 |
|---|---|---|
| 被弾後の水平初速 | 入射水平速度の逆向き、速さ `min(入射水平速度の大きさ × 0.20, 5.0)` m/s | 手前へこぼれる反応を作り、強いラリーでも追いかけられる速度に抑える |
| 被弾後の上向き初速 | +3.0m/s（入射の上下成分は引き継がない） | 約0.46m持ち上がり、落球が見える |
| 重力 | 9.8m/s² | 読みやすい放物運動 |
| 床の反発係数 | 0.50（鉛直成分だけ） | 数回跳ねて収束する |
| 接地確定 | 床衝突後の上向き速度が0.50m/s以下ならy＝半径、vy＝0に固定 | 微小なバウンドが続くのを防ぐ |
| 転がり減速 | 接地中の水平速さを3.0m/s²で減らす | 上限5m/sから約1.7秒で止まる |
| 水平停止 | 減速後の速さが0.10m/s以下ならvx＝vz＝0に固定 | 浮動小数の微小速度を残さない |
| 外周・中央の反発係数 | 0.50（境界の法線方向の水平成分だけ） | 陣を越えずに勢いを失わせる |

被弾後の水平入射がゼロなら球の水平初速もゼロ（キャラ方向の代替値を球へ流用しない）。速度やノックバック距離へ攻撃・防御・敏捷の追加倍率は掛けない。攻撃判定とラリー加算は切り替え時に消え、以後バウンドしてもダメージ・能動防御・追尾・中央通過イベントは発生しない。危険時計は継続する。

攻撃消失（`attackLossAt`）も同じ未所持球の運動へ移す。ただし、キャラに当たっていないので水平初速は**入射と同じ向き**の20%・上限5m/s、vyは `clamp(入射vy × 0.20, −3.0, +3.0)` m/sとする。人工的な上向き3m/sは与えない。床や外周へ達した成分は切り替え時に下記の境界処理を1回行う。床への負のvyは反発し、床上でvy＝0なら転がる。攻撃中は従来どおり重力なし、最初の床・外周接触で攻撃を失う。追尾中はこの消失判定を行わない。

### 球の範囲

- 球中心のxは±`ballHalfWidth`（6.175m）。zはP1側 `[r, ballHalfDepth]`、P2側 `[−ballHalfDepth, −r]`（r＝0.325m、奥行上限15.275m）。被弾・攻撃消失とも、その時刻の `ball.side`（通常の被弾では受け手陣）を使う。同時刻の中央通過があれば、通過後の陣を使う。中央際で球中心の通過より先にカプセルへ接触した場合は、従来どおり通過前の陣に残す。被弾者のsideで陣を切り替えたり、中央通過していない時計を更新したりしない。
- 中央から半径分離すため、未所持球にz＝0はない。以後の陣判定は保存した別のsideではなくzの符号を使う。投げ直さない限り別陣に入らず、転がして時計を戻せない。
- 移動先が境界上または外なら座標を境界へクランプし、外向きの速度成分だけ−0.50倍する。内向きの速度は変えない。角ではx、zの順に両成分を処理する。余った移動距離の折り返しや同一刻み内の再衝突は計算しない。
- 高さにかかわらず同じ水平範囲を使う。未所持球だけに適用するゲーム上の制限で、中央フェンスに球全般の物理壁を追加しない。投擲・追尾中の球は従来どおり中央を通る（feel.mdの世界観を維持）。

## 時刻と決定論

### 状態の形

既存の `loose` に必要な運動状態だけを追加し、静止球も同じ形式に統一する。旧形式の既定値補完・互換処理は作らない。

```ts
// loose の追加フィールド。position / startsAt は維持する。
velocity: Vec3;
motionAt: number;       // position / velocity を確定した整数時刻
nextPhysicsAt: number; // 次に運動と回収を判定する絶対フレーム境界

// PlayerState.action の追加種別
{ kind: 'hitstun'; startedAt: number; moveEndsAt: number;
  endsAt: number; velocity: { x: number; z: number } }
```

`loose` 作成時に `motionAt = 作成時刻`、`nextPhysicsAt = (floor(作成時刻 / frame) + 1) × frame` とする。初球・ラウンド再開・爆発後の供給球は床上、速度0で作る。`startsAt` は従来の時計開始用で、運動の積分起点には使わない。接地は `y === r && vy === 0`、静止はさらに水平速度0で判別できるため、重複するフラグや別modeを増やさない。

### 1F境界の更新

`frame = 1000`、1秒＝60000を維持する。境界は試合時刻0を基準に固定し、被弾ごとに刻みの位相をずらさない。最初だけ作成時刻から次の境界までの端数時間、その後は必ず1/60秒を積分する。

1. `dt = (nextPhysicsAt − motionAt) / timeUnitsPerSecond`。球のx/zに現在速度×dtを加える。
2. 空中なら `y += vy × dt − 0.5 × 9.8 × dt²`、`vy -= 9.8 × dt`。床以下で下降中ならy＝rへ寄せ、vyを−0.50倍する。反発後が0.50m/s以下ならvy＝0にする。余った時間を使って再バウンドしない。
3. 接地が確定していた区間だけ水平減速する。`s' = max(0, hypot(vx,vz) − 3.0 × dt)`、s'が0.10以下なら0、それ以外は向きを保って速さをs'へ。空中から床に着いた刻みでは水平減速せず、次の刻みから減速する。床上はy＝r、vy＝0を保ち重力を積まない。
4. x、zの境界処理を行う。`motionAt = nextPhysicsAt`、`nextPhysicsAt += frame` とし、更新後の位置で自動回収を判定する。静止中も回収のため境界を進める。

浮動小数の演算順序は上記で固定する。入力・行動境界・描画更新ごとに未所持球へ分割積分を追加しない。境界間のsim上の未所持球位置は直前の確定値。床・外周の衝突を解析的に解くのは攻撃中だけで、落球後の境界衝突は最大1Fの離散誤差を許容する。整数時刻へ再度ceilしたり、位置・速度を毎回小数桁へ丸めたりしない。

### イベントへの組み込み

- `step()` の次事象に `nextPhysicsAt` を加える。同時刻は「爆発 → 入力と行動境界 → 中央通過・防御接触・直撃／攻撃消失 → 既存looseの物理更新と回収 → ダメージ・KOの勝敗判定」。召喚が成功していれば物理更新・回収は行わない。被弾・攻撃消失でその時刻に生まれた球は、次の境界まで更新・回収しない。
- 終了境界 `at === end` にある新しい物理更新・回収は次の `step()` に渡す（既存の終了境界接触と同じ考え方）。その時刻の入力を受け取ってから1回だけ処理する。保存時に `nextPhysicsAt === state.now` でも正常な「未処理の境界」であり、次回に処理して必ず1F進める。既存の爆発優先・時計開始・勝敗の順序を壊さない。
- ノックバックはステップと同じ等速運動で、`moveEndsAt`・`endsAt`・壁到達を事象候補にする。被弾時刻自体をFへ丸めず、その整数時刻から12F／24Fを足す。押し出し区間は `[startedAt, moveEndsAt)`、硬直は `[startedAt, endsAt)`。
- result／overでは球・押し出しを進めない。次ラウンドでは全運動状態を新規作成する。爆発・召喚・回収でlooseを置き換えたら、古い物理予定を引き継がない。
- 全状態は通常のデータとしてスナップショットへ含める。乱数・描画dt・three.jsのオブジェクト・隠れた積分残時間をsimへ入れない。同じ実行環境・状態・入力・configでstateとeventsの再実行一致を必須とする。ブラウザ間のビット一致を新たに保証するものではない（0004、M2はホスト確定）。

## 回収・召喚・爆発

- 自動回収は未所持球の物理境界だけで判定する。danger中・生存・球と同じ陣・`hitstun` ではないキャラが対象。高さは**球中心y≦0.80m**、水平中心間距離≦1.20m（両方境界を含む）。速さ・上昇下降は問わず、低いバウンド中も転がり中も拾える。球半径を回収半径へ足さない。0.80mは低い球を扱う目安で、試遊で調整する。
- それ以外の既存action中の自動回収可否は変えない。回収してもactionを解除せず、catch成功・報酬にはしない。同時候補は水平距離の小さい順、同値は固定のplayer ID順。中央越しに敵陣の球を拾わない。
- 静止球にも同じフレーム判定を使い、従来の等速移動の解析解 `pickupAt` は置き換える。境界間だけ半径内を通過しても拾わない。供給球もdanger開始後の最初の物理境界で回収（時計開始と同じ境界ならそこで可）。被弾の瞬間の回収はない。
- 召喚は従来どおり行動なし・コスト1・danger中・自陣のlooseが条件。**高さ・速さ・距離に制限を加えず**空中でも呼べる。`hitstun` 中は不可。成功した入力時刻にheldへ変えて運動を消し、時計はそのまま。移動中の球を取りに行く代わりの資源消費となる。
- 爆発の陣はlooseのz符号で決める。反射で符号は変わらないため、境界間の確定位置でも曖昧にならない。期限と回収・召喚・床反発が同時なら爆発が先。床・外周・中央の反射、回収、召喚は `expiresAt` を変えない。ステップ回復の陣判定も同じzを使う。

## 画面と将来のアニメーション

- キャラのルート位置はsimの位置を使う。押し出しを表示側で重ねず、モデルの傾き・被弾姿勢だけ表示に足す。視線yawを保持してTPSへ移る（feel.md）。画面揺れや将来のルートモーションで判定位置を動かさない。
- 現在のAvatarは位置変化だけでrunを選ぶため、`hitstun` 中の押し出しを歩行と誤表示しないよう状態を渡す。被弾クリップができるまではidleを使い、sim位置の移動で押し出しを見せる。
- 球の位置は確定したsim状態間の補間で滑らかに表示する。接地して転がる見た目は水平移動量dに対し回転角 `d / r`、軸は `上方向 × 水平移動方向`。空中は離地時の表示角速度を維持するだけでよい。球の回転・姿勢は表示専用で、再生の開始・球の供給・取得時に初期化できる。物理初期位置へのクランプによる瞬間移動分を転がり距離に数えない。
- 今回追加するsim契約は上の `hitstun` と、既存hitイベントへの `direction: Vec3`（押し出し単位方向、y＝0）・`ko: boolean`。既存の `at / player / damage / position` は維持する。別のknockbackイベントや毎Fのbounceイベントは作らない。
- 将来のクリップ選択は、投げ始め＝`action.kind === 'windup'`、投げる瞬間＝`release`、被弾＝`hit`／継続姿勢＝`hitstun`、成功した跳ね返し＝`parry`、成功したキャッチ＝`catch`。`catch`／`parry` actionは成功前の構え・空振りを表し、成功イベントと混同しない。`hit.ko` は倒れるクリップを選ぶ材料にする。
- `hitstun.startedAt` と整数時刻で被弾動作の進みを復元できる。投げ始めは既存 `endsAt − throwWindup`、成功動作の起点はイベントのatを使う。将来、成功後クリップを途中スナップショットから復元する必要が生じた時点で、その起点と動作元をactionへ追加する。今回、全actionの改名・共通アニメ状態機械・クリップID・イベント履歴保存は導入しない。
- アニメーション素材・再生機構は今回作らない。表示上のヒットストップで位置更新・危険時計・入力判定を止めない（feel.md）。受け入れでは状態・イベントの材料までを確認し、最終的な手触りは後の試遊で確認する。
