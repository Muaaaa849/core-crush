## フレーム時間（`?bench=600`）

計測方法：画面更新を待たずに1フレームずつ描画し、GPU完了を待つまでの時間（ウォームアップ60フレーム後の600フレーム）。プレビューのタブは非表示扱いで、requestAnimationFrameが約1.3回/秒に制限されるため、通常の表示ループでは計測できなかった。

| バックエンド | p50 | p95 | p99 | 描画呼び出し | 三角形 |
|---|---|---|---|---|---|
| WebGPU | 5.9 ms | 7.1 ms | 8.3 ms | 246 | 274,437 |
| WebGL2 | 4.8 ms | 5.7 ms | 6.0 ms | 246 | 274,437 |

条件：ステージ全体、試合球、仮キャラ、ライト26灯、ブルーム。影なし。

## 判断と未検証

- どちらのバックエンドも、1080p・60fps（16.7ms）の予算に対して大きな余裕がある。
- バックエンド間の差（約1ms）は、GPU完了の待ち方（WebGPU：`onSubmittedWorkDone`、WebGL2：`readPixels`）の違いを含むため、優劣の根拠にしない。既定はWebGPU（非対応時は自動でWebGL2）のままにする。
- **未検証**：実表示（表示同期・合成を含む）のフレーム時間、10分戦のp95/p99、入力遅延、メモリの推移。手順：Chromeで `npm run dev` → `/?stats` を開き、プレイ開始後に計測表示を読む（feel.md「品質基準」）。
- 自動計測でプラズマフェンス・雨・VFXは未追加。M1以降の基準シーンで再計測する。
